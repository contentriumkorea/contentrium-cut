# 업데이트 즉시 시작 검수와 0.1.1 배포

사용자 요구: 오류를 자세히 검증·수정하고 배포한다. 발견한 업데이트를 누르면 지체 없이 CUT 작업을 중단하고 업데이트를 시작한다. 컴퓨터유즈 금지는 유지한다.

## 발견과 수정

| 항목 | 재현한 문제 | 수정 계약 |
|---|---|---|
| U2 | SourceMonitor의 미리보기 중단 응답을 기다리느라 업데이트 요청이 전송되지 않음. 상태 새로고침이 편집을 다시 허용함 | 클릭 즉시 로컬 업데이트 의도를 고정하고 새 작업을 차단. 서버 중단 요청을 먼저 전달하고 미리보기 종료는 독립적으로 진행. 종료 전에는 quiescence를 보고하지 않음 |
| U3 | 동기 GitHub 확인·모델 리비전 조회가 순차 인증 통신을 점유함 | GitHub 확인은 하나의 백그라운드 요청으로 합침. 모델 조회는 기존 취소 가능한 검증 worker/continuation을 사용. MAC counter 순서를 그대로 보존 |
| U4 | 재확인 중인 이미 검증된 후보를 업데이트할 수 없고, 늦은 304 응답이 중단 이후 기록을 덮을 수 있음 | 서명·만료·호환성을 다시 검사한 기존 후보는 CHECKING 중에도 시작. 확인 결과 공개 시 중단 gate를 같은 잠금 안에서 재검사 |
| U5 | 응답 유실 뒤 편집 재허용과 중복 업데이트 클릭 가능 | 요청 ID를 유지한 재시도. 성공 응답 또는 진행 중인 요청의 중복 클릭 무시. 이전 epoch의 열린 gate로는 로컬 중단을 해제하지 않음 |
| P5 | 오디오 FFmpeg 실행에 콘솔 창 억제 옵션 누락 | Windows CREATE_NO_WINDOW 적용. 입력 검사·감독 프로세스와 같은 숨김 실행 계약 |

| U6 | 느린 확인 요청이 native 인계의 10초 제한을 소진해 설치 후 활성화를 실패시킬 수 있음 | PENDING_ACTIVATION에서 기존 확인 thread가 종료될 때까지 인계 시도를 유지. 종료 후 전체 drain과 일회용 ticket 순서대로 진행 |
| U7 | 시작 응답 유실 뒤 새 확인이 실패하면 보존한 요청이 있어도 재시도를 거부함 | 새 의도를 만들 때만 발견 후보를 요구. 보존한 요청은 그대로 재시도하며 인증된 후보 거부 응답으로 잠금을 해소 |

## 즉시 시작의 경계

버튼 클릭 후 확인창·미리보기 종료·원격 메타데이터 완료를 기다리지 않고 중단 요청을 보낸다. 대기 중인 같은 인증 통신은 순서를 유지한다. CUT worker는 취소·종료를 확인하고, 이미 시작한 Adobe 트랜잭션은 반환 경계에서 중단한다. 미리보기가 종료되지 않으면 종료 대기 안내를 표시한다.

다운로드·서명·SHA-256 검증 후 **Premiere의 실제 정상 종료가 확인되어야** 플러그인 파일을 교체한다. Premiere를 강제 종료하거나, 열린 프로젝트를 닫거나, 종료를 추정하는 우회는 없다. 새 패널과 런타임의 실제 연결 증거가 있어야 COMPLETE가 된다.

## 증거

수정 전 패널 회귀 4개와 Python 회귀 4개가 실패했다. 수정 후 실제 main.js 핸들러 기반 패널 41개, 관련 Python 112개가 통과했다. 별도 probe 실패 회귀도 RED → GREEN으로 확인했다. 전체 회귀·패키지·공개 배포 결과는 아래에 실행 후 기록한다.

독립 재검수에서 U6/U7을 추가 발견하여 두 회귀의 RED를 확인하고 보완했다. 보완 후 관련 패널 42개·Python 54개가 통과했고 원 검수자가 해당 수정 승인과 남은 지적 없음으로 판정했다. 승인 범위는 소스이며 실제 설치된 앱 검증을 의미하지 않는다. 보완 전 전체 결과 Python 483/483·Node 150/150은 과거 기록으로 보존하고, 최종 수정분에서는 전체 회귀를 새로 실행한다.

최종 소스 전체 회귀: **Python 484/484 (85.221초), Node 151/151 (17,618.074 ms)**. 실패·오류·skip·제외 0. Python은 동일하게 중복 수집되는 imported TestCase를 한 번씩 실행했으며 실제 Windows 작업 종료·Silero 실행도 포함한다. 추가 실제 Windows 파일 공유·검증 worker 시험 **4/4 (0.961초)** 통과. 공급자 FFmpeg 9.0.2 패키지도 실제 다운로드해 고정 SHA-256과 FFmpeg/ffprobe 실행을 확인했다. 사용자 설치는 변경하지 않았다.

이 문서의 패널 검증은 SDK 경계 대역이며 실제 설치된 Premiere 조작이 아니다. 혼합 녹음 Community-1의 실제 모델 품질, 설치된 UXP의 자기 폴더 확인 및 0.1.0 → 0.1.1 실제 전환은 미실행이다. 0.1.2 공개와 사용자 업데이트 시험은 0.1.1 설치·활성화 확인 뒤에 진행한다.

## 실제 배포 파일 검증

0.1.1 런타임 ZIP·CCX·Setup을 만들고 별도 작업 폴더에서 실제 배포 바이트를 검증했다. ZIP 경로·CRC·설치별 비공개 파일 제외, 설정/버전 일치, CCX와 현재 플러그인 소스 일치, 동봉 Silero 모델 해시가 통과했다. frozen 런타임 29개·Setup 26개 제품 모듈은 현재 소스와 컴파일 결과가 일치한다. 압축을 푼 런타임의 `--probe`와 Setup의 `--help`는 모두 종료 코드 0이다. 실제 설치·Adobe 실행은 수행하지 않았다. 상세 크기와 SHA-256은 [패키지 증거](package-0.1.1-proof.json)에 기록했다.

Setup에 공유 모듈을 통해 AI 추론 엔진까지 중복 포함되던 빌드 경로를 수정했다. 설치기에는 모델 목록·해시 검증을 남기고, 추론은 서명된 별도 런타임에서 수행한다. 독립 검수자가 첫 설치·복구·실행·감독 경로를 확인해 해당 제외 목록을 승인했으며, 최종 Setup 크기는 93,434,377바이트다.

기동 검사에서 pyannote의 선택적 torchcodec 파일 디코더 경고(`No spec found for libtorchcodec_image`)는 남는다. 현재 제품은 FFmpeg로 읽은 mono 16 kHz PCM을 `waveform`/`sample_rate`로 전달하며 이 파일 디코더를 사용하지 않는다. 패키지 기동과 소스의 PCM 경로는 확인했지만, 이 결과를 Community-1 실제 가중치 추론 품질 검증으로 확대하지 않는다. 경고 원문은 비공개 작업 증거에 보존했다.
