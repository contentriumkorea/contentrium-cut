2026-10-06 사용자 지시: 별도 명령 전까지 컴퓨터유즈 금지. 이후 오류 검증·수정·배포를 명시적으로 요청했으므로 백그라운드 테스트·빌드·GitHub 배포를 진행한다. 설치된 Premiere 화면 조작과 새 native 결과 검증은 실행하지 않는다. 실제 공개 상태와 미실행 항목은 [최신 기록](2026-10-06-update-responsiveness.md)을 따른다. 이후의 시간순 기록은 해당 실행 당시 상태다.

이후 `남은 테스트 진행` 요청으로 보류했던 13개와 실제 Windows 파일 잠금 4개를 실행·통과했다. 추가로 확정한 최상단 컷 배치를 반영했다. 최신 근거와 과거 실패 기록은 [백그라운드 검증 기록](2026-10-06-background-acceptance.md)을 따른다. 아래 시간순 기록의 ‘13개 미실행’은 당시 상태이며 최신 상태가 아니다.

P4 백그라운드 검증: 원래 Node 40개에 실제 main.js 이벤트를 사용하는 VM 6개와 편집 요청/응답 유실·취소 처리 10개를 더한 56/56 통과. 별도 추가한 SDK 저장 실패 회귀는 RED를 확인한 뒤 수정했고 관련 싱크 29/29가 통과했다. 이는 설치된 UXP 조작이나 실제 Premiere 저장 결과의 검증이 아니다.

B1 당시 전체 소스 회귀: Python 341개 중 명시적 모델 경로가 필요한 기존 2개를 제외하고 통과, 당시 기본 Node 57/57 통과. 이후 독립 리뷰가 재현한 결함은 두 차례 수정과 재검수로 소스 범위 합격을 받았다. 새 JS↔Python 서비스 통합 회귀는 9개로 늘렸으며, S2 코드에서 9/9 통과했다. 편집 응답 유실, 서비스 재시작, 패널의 로컬 기록·신원 유실, 저장된 교정 재조회가 포함된다. 이는 S2 최종 소스 검수나 설치된 호스트 합격을 뜻하지 않는다.

S2 집중 Python 검증은 141/141, 실행된 skip 0이다. native/실제 모델 관문 3개는 실행 목록에서 명시적으로 제외했다. 앞선 실행의 현재 Python 프로세스·Windows 프로세스 목록 읽기와 임의 이름의 시험 mutex 생성/해제는 보고서에 별도 기록했다. 실제 앱 실행·종료, 설치·레지스트리·Premiere 조작은 없었고 이를 native 제품 증거에 포함하지 않는다.

S2 독립 검수에는 일반 롱폼 입력의 전체 파일 해시를 동기 요청에서 반복 계산해 패널의 8초 응답 제한과 충돌할 수 있는 문제도 포함한다. 같은 경로의 교체 미디어 검증과 함께 소스에서 해결할 관문이다. GitHub 공개 제품과 로컬 설치는 여전히 0.1.0이며 0.1.1/0.1.2 빌드·배포는 진행하지 않았다.

S2 수정 중 통합 검증: 실제 인증·서비스·작업 기록을 private stdin으로 연결한 11/11 통과, skip 0 (16614.0878 ms). 영상·음원 내용 변경, 저장된 한글 화자 교정 복원, 실행 허가의 최종 take 응답 유실과 재시작 복구를 확인했다. 패널의 개별 요청 제한은 8초를 유지하며 검증 대기는 통신 큐 밖에서 진행해 heartbeat와 취소 요청을 수용한다. 관련 패널·연결·작업 흐름 58/58도 통과했다. Windows 파일 공유 잠금과 별도 프로세스는 해당 통합 시험에서 주입된 대역이므로 실제 파일 잠금·Premiere 동작의 증거로 사용하지 않는다.

후속 수정 검증: 서버 검증 실패 후 자동 조회 반복과 대기 중인 take의 취소 경합은 관련 69/69 통과 뒤 독립 승인됐다. S2의 마지막 컷 계산 잠금 문제는 같은 검증 worker에서 계산하고 최종 take에서 등록만 하도록 변경했다. 관련 Python 182/182 (20.358 s), 해당 고정 소스에서 `npm test` 127/127 (16049.4653 ms), 모두 실행 skip 0이다. 기본 Node 시험에는 최신 JS↔Python 통합 11개가 포함된다. 백엔드 독립 재검수도 R1/R2/R3 해결과 spec/code-quality 승인을 받았으며, 실제 Windows 파일 잠금·설치·Premiere 결과 검증은 별도 관문으로 남는다.

설치 루트 재확인: 현재 Codex 프로세스에서는 일반 LocalAppData 경로와 MSIX 경로의 `active.json`이 `os.path.samefile=True`이며, 둘 모두 Windows 파일 핸들의 최종 경로가 `C:\Users\JeYun\AppData\Local\Packages\OpenAI.Codex_2p2nqsd0c76g0\LocalCache\Local\Contentrium CUT\app\active.json`이다. 두 개의 독립 설치가 있다고 판단하지 않는다. 후속 마이그레이션은 이 물리 루트를 명시적으로 고정하고 기존 데이터/저널을 보존한다. 읽기만 수행했다.

M1 이후 전체 Python 시험의 첫 실행은 테스트 대역의 전역 DLL 변경이 설치기 시험에 영향을 줘 오류창 처리 경로에서 중단됐다. 창이 실제 표시됐는지는 관찰하지 않았다. 컴퓨터유즈 없이 정확히 확인한 자체 시험 프로세스만 종료했으며, 이 실행을 통과 증거에 포함하지 않는다. 파일 저장 대역을 해당 함수로 제한하고 설치기 경로를 주입했으며, 예기치 않은 창 생성 시 즉시 실패하는 보호를 추가했다. 수정본은 독립 검수 승인을 받았다.

수정 후 최신 전체 소스 검증: Python 448/448 (56.279 s), Node 133/133 (16291.2772 ms), 실행 실패·skip 0. Python은 중복 수집된 동일 시험 41개를 한 번씩만 실행하고, 실제 프로세스 트리·시험 mutex·음성/모델 관문 13개를 명시적으로 제외했다. 이 결과는 실제 Premiere·설치된 UXP·업데이트 실행 결과를 대신하지 않는다. 현재 단계는 전체 변경 사항의 최종 소스 검수이며 제품 버전은 0.1.0으로 유지한다.

전체 115개 변경 파일의 독립 검수 결과는 보완 필요다. 중요한 결함 4개(싱크 및 카메라 원본의 같은 경로 내용 교체 허용, 상태 조회의 모델 전체 해시 지연, 캐시 정리 중 동시 중단 요청 차단, 밀집된 롱폼 편집의 작업 기록 한도)와 경미한 결함 1개(첫 캐시 설정의 NaN)를 좁은 격리 시험으로 재현했다. [보완 설계](round-2-design.md)의 FR1–FR5를 한 번의 수정 묶음으로 처리한 뒤 재검수한다. 실제 앱·설치·모델 제공자·배포 작업은 수행하지 않았다.

FR1–FR5 수정 묶음의 최신 전체 검증은 Python 465/465 (60.868 s), Node 141/141 (17509.5273 ms), 실행 실패·skip 0이다. Python의 앞선 실행은 기존 오디오 시험 하나가 새 작업 메타데이터를 DSP 함수에 직접 넘겨 오류를 냈다. 해당 호출만 실제 worker와 맞춰 고쳤고 실제 FFmpeg trim 검증은 유지했다. 이후 전체 Python을 다시 통과했으며 기존 실패 기록도 보존했다. Node 시험에 쓰인 소스는 변경되지 않아 그 141개 결과를 유지한다. 원 검수자가 정확한 수정분을 재검수하는 중이다.

현재 편집 용량은 범위 밖 보존 조각과 실패 표시용 작업 1개까지 계산해 적용 전에 검사한다. 최대 8,192개 native batch/64 MiB 기록 용량이며, 컷 편집에서는 전체 조각 2,729개 한도다. 60분·1,800구간의 5,404개 작업 사례는 소스 회귀를 통과했지만 실제 Premiere 처리 시간·성능·지원 세션 길이를 실측한 결과는 아니다. 용량을 넘으면 적용 범위를 나누거나 컷 수를 줄이도록 안내한다.

최종 소스 재검수 결과: **승인**. 원 검수자가 수정분 25개 파일/2,195줄과 고정 해시를 확인했고 FR1–FR5 모두 해결로 판정했다. 이번 수정에 남은 중요 결함은 발견되지 않았다. 따라서 소스 검수 단계는 마쳤지만 **2차 전체 완료는 아니다**. 실제 설치된 패널·Premiere 결과·모델 품질·Windows 실행 및 업데이트 동작·0.1.1 재설치와 배포, 이후 3차 검수와 0.1.2 공개가 남는다. 컴퓨터유즈 금지 상태를 유지하며 이번 단계에서는 설치·빌드·서명·배포·버전 변경을 실행하지 않았다.
