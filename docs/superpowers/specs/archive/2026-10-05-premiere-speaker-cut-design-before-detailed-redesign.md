# Premiere 화자 중심 자동 컷 편집 플러그인 설계

작성일: 2026-10-05 · 상태: Mono Studio UI 방향 확정, 실제 Premiere 연동 필수 · 제품 구현 전

## 1. 목적과 확정된 요구

Premiere에 가져온 롱폼·팟캐스트 영상을 분석해, 발언하는 사람의 카메라로 화면을 전환한 편집 가능한 시퀀스를 만든다. 사용자는 Premiere 패널에서 설정하고 결과를 계속 편집할 수 있어야 한다.

- 출연자별로 마이크가 분리된 녹음과 여러 목소리가 섞인 녹음을 모두 지원한다.
- 사용자가 사람과 카메라를 연결한다. 혼합 녹음에서는 감지된 목소리의 예시를 듣고 사람을 확인한다.
- 원본 미디어와 원본 시퀀스를 보존하고 새 시퀀스에 편집 결과를 만든다.
- 첫 제품 목표는 화자에 따른 카메라 전환이다. 영상 전체를 다시 인코딩한 파일만 전달하는 방식으로 끝내지 않는다.
- 사용자는 2026-10-05 상세 UI 시안 05의 Mono Studio 스타일을 선택했다. 실제 Premiere Pro와 연계되어 작동해야 한다는 요구를 명시했으며, 현재 선택은 UI 방향에 관한 확정이다.

검토용 확장안: **파일 선택 → 자동 싱크 → 화자 분석 → 자동 컷** 경로를 추가한다. 사용자가 이미 싱크를 맞춘 일반 시퀀스에서도 시작할 수 있다. 자동 싱크는 공통 녹음 소리 또는 신뢰할 수 있는 공통 타임코드가 있는 자료를 대상으로 하며, 근거가 부족한 파일을 임의로 정렬하지 않는다. 사용자의 자동 싱크 가능 여부 질문을 반영한 설계 확장이며, 제품 구현·검증 완료를 의미하지 않는다. 두 경로 모두 분리·혼합 녹음을 지원한다.

## 2. 첫 버전의 사용 흐름

1. 시작 방식을 선택한다. 파일 방식은 Premiere 프로젝트에서 같은 촬영 세션의 영상·녹음 파일을 선택한다. 기존 시퀀스 방식은 대상 시퀀스를 열고 전체 또는 In/Out 구간을 선택한다.
2. 파일 방식에서는 카메라별 파일 묶음, 기준 음원, 동기화에 사용할 채널, 결과에 사용할 오디오를 지정한다. 패널이 자동 싱크를 분석하고 불확실한 파일만 검토하도록 안내한다. 통과한 자료로 싱크 확인용 일반 시퀀스를 만든다. 기존 시퀀스 방식에서는 영상 트랙과 분석할 오디오 소스·채널을 지정한다.
3. 녹음 모드를 선택한다. 분리 녹음은 사람별 마이크 채널을 연결하고, 혼합 녹음은 감지 화자의 짧은 음성을 들어 사람과 연결한다.
4. 사람별 기본 카메라와 선택 사항인 전체 화면 카메라를 지정한다. 시작 카메라는 전체 화면 카메라를 기본값으로 하며, 없으면 사용자가 지정한다.
5. 분석을 실행한다. 진행 상태, 취소, 분석 실패 이유를 표시한다.
6. 컷 길이와 전환 반응을 조정한다. 음성 분석 결과를 재사용해 편집안을 다시 계산한다.
7. 별도 결과 시퀀스를 생성해 Premiere 모니터에서 재생한다. 검토 구간은 타임코드 목록으로 이동할 수 있게 한다.
8. 사용자가 결과 시퀀스를 직접 수정해 후속 편집을 이어간다.

처음부터 끝까지 무인 편집을 전제하지 않는다. 사람과 카메라를 연결하는 초기 설정 및 불확실 구간 검토를 제품 흐름에 포함한다.

### 확정된 UI 방향: Mono Studio

- 상세 시안 `output/ui-concepts/2026-10-05 17'15 UI 05 최소 설정형.png`의 시각적 분위기를 따른다. 차콜·흑백 중심, 얇은 구분선, 절제된 모서리, 흰색 주 실행 버튼을 사용한다. 작은 상태 표시 외에 보라색 등 다른 시안의 강조색을 추가하지 않는다.
- 실제 제품은 Premiere 안에서 여는 UXP 패널이다. 디자인 보드 오른쪽의 컴포넌트 비교 영역은 제품 화면에 포함하지 않는다. 패널 폭에 맞춰 화자 연결 행과 설정을 세로로 재배치하며 불필요하게 넓은 창을 요구하지 않는다.
- 기능 배치는 소스 → 싱크 → 화자 연결 → 편집 설정 → 새 시퀀스 생성 순서를 유지한다. 화자 사진은 실제 소스에서 얻을 수 있을 때만 사용하고, 없으면 중립적인 자리표시자를 쓴다.
- 연결 상태는 실제 활성 프로젝트·시퀀스 조회 결과로 표시한다. Premiere 연결과 로컬 분석 프로그램 연결을 구분하고, 연결되지 않은 상태를 초록색 성공 상태로 보여주지 않는다.
- 프로젝트·시퀀스 이름, 소스 목록, 선택 상태, 처리 진행률, 검토 구간, 생성 결과는 실제 데이터에서 표시한다. UI 시안의 예시 이름·길이·싱크 완료 문구를 초기 실제 상태로 사용하지 않는다.
- 프로젝트가 없거나 필수 매핑이 비어 있으면 해당 실행 버튼을 비활성화하고 해결할 항목을 짧게 안내한다. 분석·적용 실패를 시간이 지났다는 이유로 완료 처리하지 않는다.

## 3. 범위와 입력 조건

| 항목 | 첫 버전 설계 |
| --- | --- |
| 개발·실행 기준 | Windows, 설치가 확인된 Premiere Pro 26.5.2에서 우선 검증 |
| 영상 구성 | 같은 촬영 세션의 프로젝트 파일 선택 또는 카메라별 일반 비디오 트랙에 싱크가 맞춰진 클립 |
| 분리 녹음 | 파일·트랙·파일 내부의 개별 채널을 구별하여 사람에게 연결 |
| 혼합 녹음 | 사용자가 지정한 공통 음성 소스에서 화자 구간 분석 |
| 편집 대상 | 사용자가 지정한 카메라 트랙과 분석 구간 |
| 결과 | 파일 방식은 싱크 확인용 시퀀스와 그 시간축을 유지한 별도 편집 시퀀스; 기존 시퀀스 방식은 원래 시간축을 유지한 별도 편집 시퀀스 |
| 오디오 | 파일 방식은 선택한 음원을 싱크 위치에 배치하며 자동 게인·믹싱을 하지 않음; 컷 적용은 기준 시퀀스의 오디오 배치·길이·볼륨·효과를 유지 |
| 오류 표시 | 싱크 불확실·시간 흐름에 따른 어긋남, 불확실 화자, 영상이 없는 구간, 미디어 오프라인, 지원되지 않는 시간 매핑 |

사용자가 만든 자막·그래픽·오버레이 트랙은 복제 시퀀스에서 유지하고 카메라 편집 대상으로 선택하지 않는다. 분석 구간 밖은 원본 배치를 유지한다. 오디오 분석용 데이터는 원본의 소스 위치와 채널을 사용하며 Premiere의 마스터 오디오 처리 결과를 그대로 분석했다고 표시하지 않는다.

중첩 시퀀스 내부 편집, Premiere 고유 멀티캠의 앵글 변경, 영상·오디오의 1배속 이외 정속 재생·속도 램핑·역재생, 조정 레이어가 여러 카메라에 복잡하게 걸친 구성은 처음부터 지원한다고 가정하지 않는다. 실행 전 감지해 지원 범위를 설명하고 해당 구성의 적용을 차단한다. 구현 검증에 성공한 구성만 지원 목록에 추가한다.

무음 삭제, 대사 내용 삭제, 자막 생성, 숏폼 추출, 얼굴 추적·자동 크롭, 색보정, 자동 음성 믹싱은 기본안에 포함하지 않는다. 자동 싱크 확장안에도 드리프트를 보정하기 위한 자동 속도 변경·오디오 시간 늘이기는 포함하지 않는다.

### 자동 싱크 확장안

- **공통 타임코드:** 실제로 같은 시계에 동기화된 타임코드와 프레임레이트·날짜 경계를 확인해 배치한다. 단순히 파일마다 타임코드가 있거나 값이 모두 00:00:00:00이라는 이유로 신뢰하지 않는다. 가능한 자료는 오디오 대조로도 확인한다. 파일 수정 시각은 동기화 근거로 사용하지 않는다.
- **공통 녹음 소리:** 카메라의 현장음과 기준 녹음의 겹치는 부분을 여러 구간에서 비교해 시간 차이를 추정한다. 박수가 없어도 같은 대화가 녹음되어 있으면 분석할 수 있다. 카메라마다 시작 시간이 달라도 겹치는 녹음 구간이 있으면 정렬 대상이다.
- **분리 마이크:** 동기화에 쓴 참조 신호와 화자 분석용 개별 채널을 구별한다. 여러 마이크를 임시 비교 신호로 사용해도 원본 채널을 합쳐 저장하지 않는다. 각 파일의 공통 시계·녹음 구간을 검증하며 서로 다른 녹음기를 같은 시작점이라고 가정하지 않는다.
- **파일 분할·녹화 중단:** 카메라별 파일 묶음을 유지하되 각 조각의 실제 시간 위치를 검증한다. 파일명 순서로 이어붙여 녹화 공백을 없애지 않는다. 기준 음원과 직접 겹치지 않는 조각은 검증된 다른 녹음과의 연결이 있을 때만 같은 시간축에 넣는다.
- **긴 녹화:** 공통 녹음이 있는 시작·중간·끝의 여러 지점에서 잔여 오차를 검사한다. 일정한 위치 이동으로 맞지 않는 드리프트가 발견되면 자동 확정을 중단하고 구간과 추정 오차를 표시한다. 타임코드만 있고 비교할 음성이 없는 자료는 오디오 싱크 검증을 마쳤다고 표시하지 않는다.
- **불확실성:** 반복되는 음악·비슷한 문장, 잡음, 무음, 너무 짧은 공통 구간, 서로 모순되는 정렬 결과는 확인 대상으로 남긴다. 무음 영상에 공통 타임코드도 없으면 자동 정렬을 보장할 수 없으므로 사용자가 대응 지점 또는 오프셋을 지정한다.
- **적용 범위:** 선택한 입력 중 정렬하지 못한 파일을 조용히 누락하지 않는다. 해당 파일을 사용자가 제외하거나 정렬을 확인한 뒤에만 컷 편집으로 진행한다. 싱크에만 사용한 카메라 현장음과 최종 재생용 오디오를 분리해 중복 재생을 막는다.
- **구현 경계:** Premiere UI에는 타임코드·오디오 기반 동기화 기능이 있지만 그 메뉴를 UXP에서 그대로 호출할 수 있다고 가정하지 않는다. 로컬 엔진이 동기화 계획을 계산하고 공개 편집 API로 일반 트랙 시퀀스를 구성하는 경로를 먼저 검증한다. UI 클릭 자동화를 필수 구조로 삼지 않는다.

## 4. 기술 구조와 대안

추천 구조는 **UXP 패널 + 로컬 분석 프로세스 + 공통 편집 계획 + Premiere 실행기**다.

| 방식 | 장점 | 비용·제약 | 판단 |
| --- | --- | --- | --- |
| UXP 패널 + 로컬 분석 프로세스 | 음성 분석을 독립적으로 검증하고 긴 작업의 상태·취소를 관리하기 쉬움 | 분석 프로그램과 모델 설치·연결 관리 필요 | 첫 버전에 채택 |
| UXP Hybrid + 네이티브 분석 | 패널과 네이티브 처리를 통합 가능 | C++ 연동 및 플랫폼별 빌드·패키징 부담 | 후속 통합 대안 |
| UXP 패널 + 클라우드 분석 | 로컬 연산 부담 감소 | 업로드 시간, 사용료, 서비스 의존성 발생 | 첫 버전에서 채택하지 않음 |

- **패널:** 대상 읽기, 화자·카메라 연결, 편집 설정, 진행·검토 화면을 담당한다.
- **분석 프로세스:** FFmpeg/ffprobe로 미디어 정보와 분석용 음성을 준비한다. 파일 방식에서는 먼저 싱크 분석기가 소스별 위치·검증 근거를 반환하고, 이후 화자 분석기가 발화 구간을 반환한다. 프로젝트 범위의 독립 런타임을 사용한다.
- **편집 계획기:** 두 녹음 모드의 결과를 같은 형식으로 받아 컷 정책을 적용한다. Premiere 객체나 화면 클릭에 의존하지 않는다.
- **Premiere 실행기:** 검증된 계획을 프레임에 맞춰 별도 시퀀스에 적용한다. 지원되는 공개 API를 사용한다.

패널과 분석 프로세스는 같은 PC의 loopback 연결을 사용한다. 외부 네트워크에 서비스를 공개하지 않고 실행별 인증값으로 요청을 확인한다. 원본 음성·영상은 클라우드 분석 서비스로 전송하지 않는다. 모델을 처음 내려받는 과정은 분석 데이터 전송과 구분한다.

분석 프로세스를 UXP 내부의 일반 Node.js 자식 프로세스 기능으로 바로 실행할 수 있다고 가정하지 않는다. 개발 단계는 로컬 프로세스를 명시적으로 실행하고, 배포 단계는 별도 실행기 또는 Adobe에서 지원하는 외부 앱 실행 경로를 검증한다.

## 5. 화자 분석

### 분리 마이크

채널별 발화 활성도, 잡음 대비 음성, 다른 채널 대비 우세도를 함께 사용한다. 가장 큰 파형만으로 화자를 결정하지 않는다. 입력 게인 차이와 다른 마이크로 새어 들어간 목소리를 보정하며, 자동 보정이 모호하면 단독 발화 예시를 사용자가 확인한다.

분리 마이크 채널을 먼저 하나로 합치지 않는다. 여러 채널이 같은 혼합 음성의 복사본이면 분리 마이크 입력으로 유효하지 않음을 알려 혼합 모드로 안내한다.

### 혼합 녹음

기본 분석 엔진은 로컬 `pyannote/speaker-diarization-community-1` 파이프라인으로 설계한다. 모델 설치와 실제 Windows 실행은 아직 검증하지 않았다. 현재 공식 안내상 초기 다운로드에 Hugging Face 계정·모델 이용 조건 동의·접근 토큰이 필요하므로 초기 설치 흐름에 이를 명시한다. 사용자 대신 계정을 만들거나 이용 조건에 동의하지 않는다.

모델의 일반 화자 구간을 사용해 동시 발화를 보존한다. 한 시점에 한 사람만 남기는 결과로 겹침 정보를 대체하지 않는다. 감지된 화자 ID는 실제 이름이 아니며, 사용자가 예시 음성을 듣고 카메라와 연결한다. 모델이 제공하지 않는 신뢰도 점수를 임의로 만들어 표시하지 않는다.

긴 파일을 여러 구간으로 나눌 경우 구간 간 화자 정체성을 유지해야 한다. 구간마다 새로 붙은 화자 번호를 같은 사람으로 간주하지 않는다. 한국어 팟캐스트 샘플에서 화자 오류와 편집 정책 오류를 따로 검수한다.

음성 전사는 화자 중심 컷 편집의 필수 입력으로 삼지 않는다. 짧은 끼어들기는 발화 길이와 겹침으로 처리하며, 모든 “네”와 웃음을 의미적으로 구별한다고 약속하지 않는다.

## 6. 편집 규칙

| 상황 | 동작 |
| --- | --- |
| 한 사람의 단독 발화 | 연결된 카메라 사용 |
| 다른 사람의 충분히 긴 발화 | 최소 화면 유지 규칙을 고려해 해당 카메라로 전환 |
| 짧은 끼어들기 | 기존 화면 유지 |
| 지속적인 동시 발화 | 사용 가능한 전체 화면 사용, 없으면 기존 화면 유지 및 검토 표시 |
| 침묵 | 기존 화면 유지; 대화 시간을 삭제하지 않음 |
| 화자 판별이 모호함 | 기존 화면 유지 및 검토 표시 |
| 선택된 카메라에 영상이 없음 | 전체 화면, 직전의 사용 가능한 화면 순으로 대체; 모두 없으면 자동 적용 차단 |

분석 시작점에 명확한 단독 화자가 없으면 지정된 시작 카메라를 사용한다. 모든 선택·대체 카메라는 해당 시점에 온라인 상태의 영상이 있는지 확인한다. 시작 카메라도 사용할 수 없으면 유효한 카메라를 다시 선택하도록 안내하고 적용을 차단한다.

초기 제안값은 최소 화면 유지 2초, 짧은 끼어들기 억제 0.6초, 지속 겹침 판정 0.8초다. 고정 성능 기준이 아닌 사용자 조절값이며 샘플 검수 후 기본값을 조정한다. 파일을 사전 분석하므로 감지에 필요한 대기 시간을 그대로 화면 전환 지연으로 만들지 않는다.

## 7. 시간·데이터·원본 보존 계약

- 파일 방식의 동기화 계획은 촬영 세션, 기준 소스, 소스별 시간 차이, 사용한 근거와 검증 구간, 잔여 오차, 누락·불확실 상태를 기록한다. 샘플 단위 추정값과 실제 Premiere 배치값을 함께 보관하며 영상 프레임 경계에 맞추는 오차를 숨기지 않는다. 싱크 확인용 시퀀스를 생성한 뒤 아래 계약의 기준 시퀀스로 삼는다.
- 입력 스냅샷은 프로젝트·시퀀스 식별자, FPS 분수, 분석 범위, 트랙·클립 식별자, 실제 소스 경로, 타임라인 시작/끝, 소스 In/Out, 채널 선택, 속도·역재생 여부, 효과·링크 상태를 기록한다.
- 소스 시간과 시퀀스 시간을 구별한다. 지원하는 1배속 클립은 `소스 In + (시퀀스 위치 - 클립 시작)` 관계로 매핑한다.
- PCM 샘플 위치와 시퀀스 프레임·Premiere TickTime 사이의 변환 규칙을 하나로 유지한다. FPS를 29.97 같은 근사 소수로 누적 계산하지 않는다. JavaScript 정밀도를 넘는 tick 정수는 JSON 문자열로 전달한다.
- 분석 결과는 구간별 화자 집합, 근거 유형, 겹침·검토 사유를 포함한다. 프레임 정렬 전 원래 분석 경계도 보관한다.
- 편집 계획은 반열린 구간 `[시작 프레임, 끝 프레임)`, 카메라·소스 클립, 선택 이유, 검토 사유, 입력 스냅샷 식별자를 담는다. 길이가 0인 컷, 소스 범위를 벗어난 컷, 공백, 불필요한 중첩을 거부한다.
- 적용 직전 원본 시퀀스가 분석 때와 같은지 다시 확인한다. 변경되었으면 기존 계획을 조용히 적용하지 않고 다시 읽도록 안내한다.
- 결과 구간에 맞춘 클립 In/Out 변경은 허용하되, 같은 시퀀스 시점에서 선택한 원본 카메라와 동일한 소스 프레임을 표시해야 한다. 클립 효과·크기·위치·키프레임 시간 관계·오디오 연결 상태를 보존하는 복제/트리밍 방식을 실제 Premiere에서 검증한다. 효과가 사라지는 재배치 방식으로 자동 대체하지 않는다.
- API의 Action 생성과 트랜잭션은 대상 버전의 `lockedAccess` 요구를 따른다. 모델 계산이나 대용량 파일 처리를 Premiere 잠금 안에서 수행하지 않는다.

## 8. 취소·재시도·검토

작업 상태는 준비 → 싱크 분석·검토(파일 방식) → 싱크 시퀀스 구성(파일 방식) → 화자 분석 → 화자 연결 → 편집안 준비 → 적용 → 검증 → 완료로 구분한다. 실패와 취소는 별도 상태다. 분석 중 취소하면 새 시퀀스나 추가 컷을 생성하지 않는다. 파일 방식에서 이미 만든 싱크 확인용 시퀀스는 완료된 컷 결과와 구분한다. 적용 중에는 안전한 API 작업 경계에서 취소한다.

결과 시퀀스는 검증을 마치기 전까지 작업 중으로 표시한다. 중단된 결과를 완료 결과처럼 표시하지 않는다. 자동 정리는 현재 작업이 만든 시퀀스로 범위를 제한하며 원본·사용자 편집 시퀀스를 삭제하지 않는다. API에서 안전한 정리가 검증되지 않으면 중단 결과를 명시해 사용자가 식별할 수 있게 남긴다.

음성 분석 캐시는 소스 식별 정보·범위·채널·모델 버전·분석 설정으로 구별한다. 컷 길이만 바꾸면 분석을 반복하지 않는다. 재적용은 사용자 편집이 없는 현재 작업의 미완성 결과만 정리하거나 새 결과를 만들며, 기존 결과에 중복 컷을 덧붙이지 않는다.

검토는 실제 Premiere 결과 시퀀스를 재생하는 방식으로 한다. 패널은 문제가 있는 타임코드로 이동하고 화자 연결·컷 정책을 수정할 수 있게 한다. 임의의 외부 미리보기만 통과했다고 Premiere 결과 검수를 대신하지 않는다.

## 9. 구현 순서와 완료 기준

아래는 구현 계획 작성에 사용할 검증 순서다. 현재 구현·설치 완료를 의미하지 않는다.

1. **Premiere 연결 검증:** 먼저 실제 Premiere에서 UXP 패널을 로드하고 현재 프로젝트·시퀀스·소스 경로·채널을 읽는다. 테스트용 복제 시퀀스에 정해진 컷 3개를 만들고 그 시퀀스를 실제 타임라인에 열어 재생한다. 생성된 클립 구간을 API로 다시 읽어 계획과 비교하고 오디오와 영상 효과 보존을 확인한다. 이 작은 연동 검증을 통과한 뒤 자동 분석 기능을 연결한다.
2. **자동 싱크 경로:** 공통 타임코드·공통 음성으로 동기화 계획을 만들고, 시작 시간이 다른 파일·분할 파일·긴 녹화의 싱크 확인용 시퀀스를 생성한다. 모호한 경우를 통과시키지 않는지 검증한다.
3. **분리 녹음 경로:** 채널 분석 → 화자 매핑 → 공통 편집 계획 → 실제 시퀀스 생성까지 연결한다.
4. **혼합 녹음 경로:** 모델 설치·실행, 화자 예시 확인, 동시 발화, 긴 구간의 화자 일관성을 검증한다.
5. **사용 흐름:** 진행·취소·재시도, 캐시, 싱크·화자 검토 구간 이동, 편집 정책 변경을 연결한다.
6. **통합 검수·설치:** 실제 한국어 팟캐스트 샘플과 긴 시퀀스로 확인한 후 설치 방법 및 검증된 지원 범위를 전달한다.

| 검증 항목 | 합격 기준 |
| --- | --- |
| 실제 호스트 연결 | 설치된 Premiere 안에서 UXP 패널 실행 → 현재 프로젝트·시퀀스 읽기 → 복제 시퀀스에 3개 컷 적용 → 결과 재조회·타임라인 재생까지 실제 수행 |
| 원본 보존 | 실행 전후 원본 시퀀스의 구조·오디오 설정·소스 연결과 입력 파일 내용에 변경이 없음 |
| 자동 싱크 | 정답 오프셋이 있는 검증 자료에서 영상 배치 오차가 출력 시퀀스의 1프레임 이내이며, 긴 파일의 시작·중간·끝에서 확인; 모호한 자료·드리프트는 자동 통과하지 않음 |
| 입력 누락·녹화 공백 | 선택한 모든 파일이 배치 또는 검토 대상으로 기록되고, 실제 녹화 중단 구간이 임의로 제거되지 않음 |
| 시간 정확도 | 확정된 편집 계획의 컷이 지정 프레임에 생성됨; 60분 이상 검증 시퀀스 끝에서 누적 시간 이동이 없음 |
| 영상 연결 | 사용 가능한 카메라 영상이 있는 구간에 의도하지 않은 검은 화면·빈 틈이 없음 |
| 오디오·효과 | 화면 전환 전후 오디오가 연속이고 기존 설정 및 지원하는 영상 효과가 유지됨 |
| 두 녹음 방식 | 실제 분리·혼합 한국어 샘플에서 모두 화자 연결과 결과 생성이 작동하며 오류 구간을 검토 가능 |
| 편집 정책 | 짧은 끼어들기·침묵·지속 겹침이 정해진 규칙대로 처리됨 |
| 실패·복구 | 취소·모델 누락·오프라인 미디어·분석 후 원본 변경을 완료로 오인하지 않음 |
| 사용 가능성 | 설치한 패널에서 실제 결과 시퀀스를 재생하고 수동 수정할 수 있음 |

화자 인식률, 처리 속도, 최대 동시 화자·카메라 수는 실측 전에 수치로 보장하지 않는다. 실측 결과와 실패 사례를 보고하고 지원 범위로 확정한다. 두 입력 방식 중 하나만 작동하면 요청 기능이 완료된 것으로 보지 않는다.

실제 호스트 연결의 증거에는 Premiere 버전, 원본·결과 시퀀스 식별자, 계획·실제 컷 경계 비교, 재생 확인 결과를 포함한다. 브라우저에서만 동작하는 화면이나 가짜 Premiere 응답을 이용한 테스트는 개발 보조 자료로 구분하며 실제 연동 완료의 근거로 사용하지 않는다.
