# Contentrium CUT — Mono Studio 패널·상태·인터랙션 상세 설계

작성: 2026-10-05 · 상태: 구현 전 UI 명세 · [전체 설계](../2026-10-05-premiere-speaker-cut-design.md)

사용자가 선택한 상세 시안 05의 분위기를 실제 Premiere 도킹 패널로 옮긴다. 제품명은 **Contentrium CUT**, Mono Studio는 시각 스타일이다. 기존 시안 이미지의 제목을 최종 제품명으로 간주하지 않는다. 시안 오른쪽의 컴포넌트 확대 비교 영역은 제품에 넣지 않는다. 넓은 디자인 보드를 그대로 축소하지 않고 좁은 패널의 읽기 순서에 맞춰 재배치한다. 아래 치수·색상은 구현과 사용성 검증을 위한 제안 토큰이다.

## 1. 시각 원칙

- 차콜 바탕, 밝은 본문, 얇은 구분선, 작은 모서리, 흰색 주 버튼을 유지한다.
- 장식용 KPI 카드·큰 인물 사진·무지개 파형·그라데이션·보라색 강조를 추가하지 않는다.
- 화자 행, 채널, 카메라를 한눈에 연결한다. 전체 화면은 사람 카드와 분리한다.
- 이름·길이·연결·완료·검토 건수는 실제 데이터에서 가져온다. 샘플 EP.12나 48:32를 초기 실제 데이터처럼 넣지 않는다.
- 패널이 제공하는 정보는 설정·진척·검토다. 실제 영상 재생의 기준은 Premiere 프로그램 모니터다.

### 디자인 토큰

| 역할 | 제안값 | 사용 |
| --- | --- | --- |
| 배경 | #17181A | 패널 전체 |
| 보조 표면 | #1C1E20 | 접힌 상세·검토 영역 |
| 입력 | #222427 | 선택·숫자·드롭다운 |
| 입력 hover | #2C2E31 | 마우스 진입 |
| 경계선 | #36383B, 1px | 행·입력 구분 |
| 주요 글자 | #F5F5F3 | 제목·값·본문 |
| 보조 글자 | #A6AAA9 | 설명·단위·메타데이터 |
| 주 버튼 | #F5F5F3 / 글자 #17181A | 결과 생성 |
| 포커스 | 밝은 2px 외곽선 + 2px 간격 | 키보드 선택 |
| 연결 상태 | 작은 연두 점 + 텍스트 | 실제 연결됨에만 사용 |
| 주의·오류 | 아이콘·라벨·경계선 | 색상만으로 구별하지 않음 |

기본 간격은 4/8/12/16/20/24px. 입력 모서리 4px, 기본 버튼 4px, 일반 구획은 카드 그림자 없이 구분선으로 나눈다. 아이콘은 동일 계열의 단순 선형 16px, 장식 로고보다 기능 라벨을 우선한다.

글꼴은 Windows 시스템 한국어 sans-serif를 우선하고 추후 번들 폰트가 필요하면 라이선스를 확인한다. 제품 제목 18px semibold, 섹션 제목 14px semibold, 본문·입력 13~14px, 보조 12px. 시간·숫자는 tabular numerals를 적용하되 UXP에서 실제 지원하는 스타일만 사용한다. 설명을 모두 10px로 줄여 밀어 넣지 않는다.

## 2. 크기와 반응형 구성

| 패널 폭 | 구성 |
| --- | --- |
| 320~399px | 기본 권장 좁은 패널. 제목/설명 아래 입력, 화자 행 2줄 |
| 400~559px | 라벨과 짧은 입력을 한 줄 배치, 화자 이름·예시·카메라 2줄 |
| 560px 이상 | 화자 연결 한 줄 가능, 검토 목록의 사유와 시간 동시 표시 |
| 320px 미만 | 필수 동작은 보존, 설명 줄바꿈. 읽기 불가하면 폭 확장 안내 |

높이는 가변이며 본문 한 영역만 스크롤한다. 헤더와 하단 실행 영역은 가능하면 고정한다. 실제 UXP 레이아웃에서 sticky 지원이 부족하면 헤더/본문/푸터를 별도 컨테이너로 배치한다. 브라우저의 CSS 지원을 그대로 가정하지 않는다. 125/150/200% Windows 배율에서 잘림과 겹침을 시험한다.

개별 카드마다 세로 스크롤을 만들지 않는다. 목록이 길 때는 검색·필터를 사용하고 필수 상태를 카드 밖에도 표시한다. 경로는 말줄임하되 전체 경로 보기·복사를 제공한다. 외국어 긴 파일명과 긴 한국어 시퀀스명으로 확인한다.

## 4. 헤더와 연결 상태

헤더에는 제품명, 대상 프로젝트·시퀀스, 연결 상세 열기만 둔다. 사용자 계정 아바타·ChatGPT 로그인 버튼을 기본 주 흐름에 넣지 않는다.

| 상태 | 표시 | 사용 가능한 동작 |
| --- | --- | --- |
| 프로젝트 없음 | `Premiere 프로젝트를 열어 주세요` | 연결 도움말·설정 |
| 프로젝트 있음, 시퀀스 없음 | 프로젝트명 + `시퀀스 미선택` | 프로젝트 클립 경로 |
| Companion 미실행 | `로컬 분석 프로그램 실행 필요` | 실행·다시 연결 |
| 모델 미준비 | `화자 분석 모델 준비 필요` | 모델 관리 |
| 준비 | 실제 프로젝트·엔진 준비 상태 | 입력에 맞는 분석 |
| 버전 불일치 | `패널과 분석 프로그램 버전을 맞춰 주세요` | 버전 확인 |

연결 상태를 누르면 Premiere 버전, Companion 버전, 모델·장치, 마지막 응답 시각을 접힌 영역으로 표시한다. 정상일 때 구현 용어를 본문에 계속 노출하지 않는다. 패널을 다시 열면 저장된 초록 상태부터 보여주지 않고 실제 연결 확인 중으로 시작한다.

프로젝트가 바뀌면 현재 작업의 대상을 상단에 계속 표시하고 `다른 프로젝트가 활성화되어 있습니다`를 안내한다. 입력을 자동 교체하지 않는다. 사용자가 새 대상을 읽을 때 이전 작업과 새 작업을 구별한다.

## 5. 소스 화면

### 프로젝트 클립 모드

`선택 항목 가져오기`는 현재 Premiere 선택을 읽는다. 실제 선택 API가 해당 구성에서 지원되지 않으면 프로젝트 항목 목록에서 직접 선택하는 경로를 제공한다. 운영체제 임의 폴더 전체를 자동 탐색하지 않는다.

한 행의 정보는 사용 여부, 파일명, 카메라/녹음 역할, 길이, 채널 수, 온라인 상태다. 상세에는 실제 경로·영상 FPS·오디오 샘플레이트·스트림을 표시한다. 파일 묶음에는 포함 조각 수와 녹화 공백이 있을 수 있음을 표시한다. 삭제 버튼의 의미는 입력에서 제외이며 원본 삭제가 아니다.

세 가지 오디오 역할을 명확히 나눈다: `싱크 비교용`, `화자 분석용`, `결과 재생용`. 하나의 파일이 여러 역할을 가질 수 있지만 출력 오디오는 명시적으로 선택한 것만 포함한다.

### 현재 시퀀스 모드

시퀀스명·해상도·FPS·길이를 읽고 `전체`/`In–Out`을 제공한다. 범위 변경은 음성 분석이 끝난 뒤의 편집 설정 변경과 구별한다. In/Out 경계가 없으면 정확한 원인을 안내한다.

비디오 트랙에는 카메라 역할/보호 역할을 지정하고 오디오에는 파일·채널까지 선택한다. 트랙 A1이 곧 사람 1이라고 가정하지 않는다. 분석이 소스 오디오 기준이며 Premiere 마스터 효과는 반영하지 않는다는 설명을 오디오 선택 근처에 한 번 표시한다.

## 6. 싱크 화면

싱크 전에 기준 녹음, 방식(자동/공통 타임코드/공통 음성/수동), 카메라 묶음, 출력 FPS를 확인한다. 자동 모드는 근거를 검사해 선택하며 파일 생성 시각을 기준으로 삼지 않는다.

| 상태 | 화면 | 다음 동작 |
| --- | --- | --- |
| 미분석 | 설명 + `자동 싱크` | 시작 |
| 분석 중 | 현재 파일·단계·측정 가능한 진척·취소 | 기다리거나 취소 |
| 근거 부족 | 해당 파일·이유·검토 | 오프셋·대응점 수정 또는 제외 |
| 타임코드만 검증 | `타임코드 기준 · 음성 대조 없음` | 근거 확인 |
| 드리프트 | 시작/중간/끝 차이와 검토 구간 | 수동 보정 자료 선택 |
| 준비 | 배치된 파일 수·제외 수·미해결 수 | 싱크 시퀀스 만들기 |

오프셋은 부호 있는 시간과 프레임을 표시한다. 내부 sample/tick 정밀도는 상세에 보존한다. 소수 초를 반올림한 화면 값으로 다시 계산하지 않는다. `+1프레임`, `−1프레임` 조정, 명시적인 값 입력, 다시 검사 동작을 제공한다.

싱크 검토 이동은 사용할 수 있는 원본/싱크 시퀀스를 대상으로 한다. 아직 존재하지 않는 결과 시퀀스로 이동한 것처럼 표시하지 않는다. 생성한 싱크 시퀀스명과 편집 시퀀스명을 구별한다.

## 7. 화자 분석과 연결

### 개별 마이크

분석 전 채널과 사람을 연결한다. 파일명+스트림+채널 표기로 식별하며 각 채널 예시를 들을 수 있다. 모노/스테레오/멀티채널을 이름만으로 판단하지 않는다. 채널 복사 의심·누음·클리핑은 라벨과 설명으로 표시한다.

분석 후에는 발화 총량, 겹말·검토 구간을 제공한다. 음량이 큰 사람을 주요 출연자로 자동 표시하지 않는다. 단독 예시가 없어서 보정이 어려우면 예시 구간 지정 또는 혼합 모드 선택을 안내한다.

### 혼합 녹음

분석 전에는 분석 음원과 인원 힌트(자동 / 알고 있는 수)를 받는다. 고정 인원은 선택 사항이며 새로운 목소리·화면 밖 발화 가능성을 설명한다. 분석 결과의 모든 임시 ID를 실제 사람으로 검토할 수 있게 한다.

한 화자 행의 구성은 다음과 같다.

| 구성 | 내용·동작 |
| --- | --- |
| 식별 | A/B 등 중립 ID, 사용자가 바꾼 표시명 |
| 예시 | 떨어진 위치의 단독 발화 2~3개를 제안, 원래 시간 표시 |
| 재생 | 4~8초를 초기 목표로 하되 유효 단독 구간 길이에 맞춤 |
| 카메라 | 온라인 후보, 역할, 실제 가용 범위 확인 |
| 상태 | 연결됨 / 연결 필요 / 다른 화자와 섞임 의심 |
| 상세 | 병합, 해당 구간 화자 변경, 예시 바꾸기 |

예시 길이와 개수는 제안값이다. 겹말·무음만 있는 구간을 억지로 깨끗한 음성 예시로 표시하지 않는다. 모델 결과만으로 얼굴 사진을 자동 붙이지 않는다. 썸네일을 표시한다면 사용자가 연결한 카메라의 실제 프레임이며 자동 신원 확인의 증거가 아니다.

예시 재생 중 다른 행 재생을 누르면 이전 재생을 멈춘다. 샘플 로딩·실패·중지 상태를 구분한다. 실제 UXP 오디오 재생이 미지원이면 동일한 원본 스트림·채널을 들을 수 있는 검증된 Premiere 재생 경로만 대체로 사용한다. 전체 믹스로 이동하는 것은 개별 채널 확인을 대신하지 않는다. 채널 재생을 보장할 수 없으면 `채널 예시 재생 확인 필요`를 표시하며 미확인 연결을 통과시키지 않는다. 재생 아이콘만 움직이는 가짜 파형을 만들지 않는다.

WIDE 행은 인물 행 아래 별도로 둔다. `없음`을 허용하며, 적합한 WIDE·투샷이 모두 없으면 지속 겹말에 현재 화면을 유지하고 검토 표시한다는 설명을 보여준다. WIDE와 투샷 모두 실제 포함된 사람을 사용자가 지정한다. 대체용으로 연결한 화면에 해당 사람이 실제 보인다고 가정하지 않는다. 예비 카메라도 사용자가 명시적으로 지정하며 없음을 허용한다.

## 8. 편집 설정

설정은 음성 분석을 다시 하지 않고 계획을 갱신할 수 있어야 한다. 값 변경 중에는 아직 계획에 반영되지 않았다는 표시를 하고 확정 시 재계산한다. 드래그 움직임마다 새 모델 작업을 만들지 않는다.

| 입력 | 기본·제안 범위 | 검증·설명 |
| --- | --- | --- |
| 최소 화면 유지 | 2.0초 / 0.5~6.0초, 0.1초 간격 | 실제 프레임 길이를 함께 확인 가능 |
| 짧은 반응에 화면 유지 | 켜짐 | 길이 기준, 대사의 의미를 판독하는 기능 아님 |
| 짧은 반응 기준 | 고급, 0.6초 / 0.2~1.5초 | 기준 이하 억제. 꺼짐은 억제 정책을 건너뜀 |
| 지속 겹말 기준 | 고급, 0.8초 / 0.3~2.0초 | 기준 이상 연속 겹말에 적용 |
| 겹말 화면 | 전체/투샷 우선 | 없으면 현재 화면 유지+검토 |
| 시작 화면 | WIDE 제안 또는 사용자 선택 | 처음부터 단독 화자가 확실하면 연결 카메라 우선 |

상호 모순을 피하려고 의미를 분리한다. 짧은 반응 옵션이 꺼져도 최소 화면 유지와 겹말 규칙은 유지한다. 숫자 필드는 빈 값·음수·NaN을 허용하지 않고 잘못된 값을 조용히 기본값으로 바꾸지 않는다. 범위 밖 입력은 허용 범위를 보여주고 적용하지 않는다.

카메라 고정 수정은 검토 화면에서 제공한다. 화면 설정에 사용자가 이해할 수 없는 model threshold·embedding distance·tick 수를 노출하지 않는다. 상세 진단에서만 기술값을 볼 수 있다.

## 9. 검토 화면

기본 패널에서 `확인 필요 N`을 누르면 같은 패널의 검토 화면으로 들어간다. 뒤로 가면 입력·스크롤·작업 대상을 유지한다. 검토 화면은 별도 웹 편집기를 열지 않는다.

상단은 필터(전체/싱크/화자/겹말/영상/지원 제한), 정렬은 기본 시간순이다. 적용 차단 항목은 별도 표시하되 목록을 무작위 재정렬하지 않는다. 각 행은 시작–끝, 유형, 사유, 다음 행동을 가진다.

예시: `00:18:42:10–00:18:45:02 · 겹말 · 전체 화면 없음 · 현재 화면 유지`. 한 행을 열면 분석 근거·연결된 사람·현재 카메라·대체 후보를 보여준다. `이 구간 보기`, `화자 수정`, `카메라 고정`, `그대로 사용`을 상황에 맞게 제공한다.

`그대로 사용`은 해결 가능한 검토 사항을 확인했다는 기록이다. 미디어 없음·지원 안 되는 시간 매핑·고정 충돌 같은 하드 차단을 무시하는 버튼이 아니다. 확인 후에도 원래 사유는 이력에 남긴다.

영상 이동은 명시한 대상 시퀀스와 시간으로 수행한다. 다른 시퀀스가 열려 있으면 대상 정보를 표시하고 실제 선택된 결과를 확인한다. 검토용 구간 반복 재생은 호스트 제어 지원이 확인된 경우에만 제공한다.

## 10. 주 버튼과 진행 표시

하단 주 버튼은 기본적으로 `편집 시퀀스 만들기`다. 사전 단계별 동작은 각 섹션의 버튼으로 제공한다. 분석·동기화·적용을 같은 버튼 이름 아래 몰래 연쇄 실행하지 않는다.

| 조건 | 주 버튼 | 설명 |
| --- | --- | --- |
| 입력·모델·분석 미완료 또는 확정 세션 화자의 필수 카메라 미연결 | 비활성 | 바로 위에 가장 먼저 해결할 항목 1개 |
| 검토 경고만 있고 유효 계획 준비 | 활성 | 예상 전환 수·검토 수·결과 길이 표시 |
| 하드 차단 항목 존재 | 비활성 | 해당 검토 항목 열기 |
| 생성 요청 접수 | 중복 실행 비활성 | 요청 처리 중 |
| 적용 중 | 적용 단계·안전한 취소 | 실제 처리 묶음 수 표시 |
| 검증 중 | `생성 결과 확인 중` | 완료 표시 안 함 |
| 성공 | `결과 시퀀스 열기` | 결과명·전환 수·검토 수·검증 상태 |
| 부분 실패 | `중단된 결과 확인` | 오류·원본 보존·재시도 방법 |
| 업데이트 클릭 이후 | 모든 편집 실행 비활성 | 중단·다운로드·설치·재시작 확인 단계 표시 |

정상 분석한 국소 구간의 판별 불가는 검토 경고로 구분하며, 확정 화자의 필수 연결 누락과 혼동하지 않는다. 비활성 클립·출력이 꺼진 카메라 트랙은 사용 가능한 영상으로 표시하지 않고 사용자가 원본 설정을 확인한 뒤 다시 읽도록 안내한다. 자동으로 켜서 가용 범위를 늘리지 않는다.

진척이 정확한 단계는 `12/24 파일`처럼 분모를 표시한다. 모델 내부 작업량을 모르면 단계명과 경과 시간만 표시한다. 시간을 기준으로 가짜 100%를 만들지 않는다. 취소 요청 뒤에는 확인 전까지 `취소 중`이다.

버튼과 작은 재생 아이콘도 실사용 가능한 클릭 영역을 확보한다. 주 버튼 높이 40px, 일반 입력 32~36px, 작은 아이콘 버튼은 최소 28px 영역을 제안한다. 긴 한글 버튼은 줄여 읽기 어렵게 만들지 않는다.

| 상황 | 표시 문구 | 액션 |

| 발화 없음 | `분석한 범위에서 발화를 찾지 못했습니다` | 범위·채널 확인 |

재연결 전 작업이 실패했다고 단정하지 않는다. 반대로 연결이 돌아왔다고 작업 완료로 처리하지 않는다. 서버 상태와 호스트 결과를 확인한다. 선택 입력이 자동으로 초기화되지 않아야 한다.

## 12. 모델 관리와 개인정보

모델 관리에는 개별 채널 VAD·혼합 화자 모델을 역할별로 나눈다. 다운로드 크기, 저장 폴더, 이용 조건·출처, 준비 상태, CPU/GPU, 파일 검증 결과를 표시한다. 실제 파일 크기를 읽기 전 예상 숫자를 확정값으로 보여주지 않는다.

공급자 로그인·조건 동의가 필요하면 사용자가 해당 공식 흐름에서 진행한다. 입력한 토큰은 마스킹하고 저장 여부를 보여준다. 토큰을 프로젝트에 포함하지 않는다. 사용자 시스템 Python을 임의 변경하지 않고 독립 런타임을 설치하는 구조를 설명한다.

기본 패널은 `이 PC에서 분석`을 표시한다. 선택적인 외부 AI를 추후 연결하면 이 표시는 해당 실행의 실제 전송 여부와 일치해야 한다. 모델 다운로드와 GitHub 버전 확인·업데이트 파일 다운로드는 인터넷 연결이며 음성 업로드와 구별한다. 진단 내보내기에는 포함 파일·경로 정보 범위를 보여주며 기본적으로 원음·대사는 제외한다.

## 13. 키보드·접근성·실제 UI 검수

- Tab 순서는 헤더 → 소스 → 싱크 → 화자 → 설정 → 검토 → 실행이다. 비활성 입력은 이유를 읽을 수 있어야 한다.
- 포커스 외곽선을 없애지 않는다. Enter/Space는 패널 안에서 해당 컨트롤에 포커스가 있을 때만 처리하며 Premiere 전역 재생 단축키를 가로채지 않는다.
- Escape는 열린 드롭다운·팝오버·확인 창을 닫는다. 분석 취소와 프로젝트 변경을 같은 키에 숨기지 않는다.
- 이름 없는 아이콘 버튼은 허용하지 않는다. 재생·중지·상세의 접근 가능한 라벨을 제공한다.
- ON/OFF는 손잡이 위치·텍스트로 구분하고 상태 점의 색만 보고 판단하지 않는다.
- 드롭다운은 아래 공간이 부족하면 위치를 조절한다. 화면 밖 메뉴·푸터 겹침·스크롤 잠김을 확인한다.
- 320/400/560px 폭과 높은 화면 배율, 긴 경로·다수 화자·네트워크 없음·모델 없음·분석 완료 전 상태를 실제 UXP에서 검사한다.
- UI 스크린샷 검수와 실제 호스트 동작 검수를 분리한다. 정적인 디자인이 통과해도 연결·생성·재생이 검증된 것은 아니다.

## 14. 화면 완성의 기준

소스부터 결과까지 모든 상태에 다음 액션이 존재해야 한다. 정상·로딩·빈 값·실패·취소·재연결·중단 결과가 모두 설계와 일치해야 한다. 사용자는 어느 프로젝트에 무엇을 만들지, 아직 무엇을 확인해야 하는지, 원본이 보존되는지를 패널에서 알 수 있어야 한다.

화면 디자인은 기존 선택 이미지를 기준으로 구현하되 불필요한 장식이나 다른 시안의 강조색을 섞지 않는다. 실물 Premiere 안에서 읽기·클릭·입력·재생·생성까지 검수하기 전에는 UI 또는 연동 완성으로 선언하지 않는다.

## 15. 자동 업데이트 알림과 진행 화면

버전은 설정의 `정보·업데이트`에 표시하고 제품명 뒤에 `릴리즈`, `최신판`을 붙이지 않는다. 확인은 패널을 열 때 비동기로 시작한다. 업데이트가 없으면 배너·팝업·성공 토스트를 띄우지 않는다. 확인 실패는 설정에 마지막 성공 시각과 함께 남기고 편집을 계속할 수 있다.

새 버전이 있으면 연결 상태 아래, 소스 입력 위에 얇은 구분선으로 나눈 인라인 알림을 넣는다. 기본 표면색·흰색 버튼을 유지하고 큰 색상 카드·중앙 강제 팝업은 추가하지 않는다. 내용이 길면 변경 내용만 접고 버튼은 바로 보이게 한다. 320px 폭에서는 버튼을 다음 줄에 배치한다.

```text
Contentrium CUT                         설정
Premiere 연결됨 · 분석 엔진 준비됨
─────────────────────────────────────
업데이트가 있습니다
현재 0.1.0 → 새 버전 0.2.0
변경 내용 보기 · 다운로드 크기
업데이트하면 진행 중인 모든 CUT 작업이 중단됩니다.
[업데이트]                 [나중에]
─────────────────────────────────────
소스 · 싱크 · 화자 · 편집 설정
```

위 버전은 화면 구조 예시다. 실제 버전·발행 시각·다운로드 크기는 검증된 배포 메타데이터에서 읽으며 고정 샘플을 제품에 넣지 않는다. 재시작이 필요한 후보에는 클릭 전에 `설치 과정에서 Premiere를 저장하고 종료해야 합니다`를 함께 표시한다.

`업데이트`를 누르면 즉시 모든 실행 버튼을 잠그고 진행 화면으로 전환한다. 동의를 다시 묻는 앱 모달은 없다. `나중에`는 현재 세션의 큰 알림을 접으며 다음 패널 진입 시 다시 확인한다. 같은 세션에서 1~2초마다 알림을 다시 띄우지 않는다.

| 상태 | 표시 문구 | 가능한 동작 |
| --- | --- | --- |
| 작업 중단 요청 | `업데이트를 위해 작업을 중단하고 있습니다` | 단계 보기. 새 분석·생성 불가 |
| 호스트 명령 반환 대기 | `편집 명령 중단을 확인하고 있습니다` | 진행 중인 프로젝트·대상 표시 |
| 다운로드 | `업데이트 파일 다운로드 중` + 실제 바이트 | 교체 전 취소 |
| 서명·파일 확인 | `업데이트 파일을 확인하고 있습니다` | 검증 전 설치·완료 불가 |
| 호스트 종료 필요 | `프로젝트를 저장하고 Premiere를 종료해 주세요` | 독립 업데이트 창에서 진행 상태 유지 |
| 설치 | `Contentrium CUT 설치 중` | 설치 권한 창이 필요하면 안내 |
| 설치 후 확인 대기 | `Premiere를 다시 열어 업데이트를 확인해 주세요` | 새 설치 버전·확인 대기 표시 |
| 실제 연결 확인 | `새 버전 연결을 확인하고 있습니다` | 아직 편집 실행 불가 |
| 완료 | `Contentrium CUT 업데이트가 완료되었습니다` | 버전·변경 내용, 중단 작업 보기 |
| 교체 전 실패 | `업데이트를 진행하지 못했습니다` | 재시도 또는 정상 확인 후 기존 작업 다시 실행 |
| 복구 진행 | `이전 버전으로 복구 중입니다` | 원본·설정 보존 안내 |
| 복구 실패 | `복구 설치가 필요합니다` | 공식 복구 파일·진단. 작업 실행 차단 |

설치와 복구가 끝나도 중단 작업을 자동 실행하지 않는다. 분석 결과·매핑·사용자 교정은 유지하고 각 작업의 실제 완료·중단 상태를 다시 보여준다. 부분 시퀀스는 `중단된 결과`로 구별하며 업데이트 성공을 편집 성공으로 바꾸지 않는다.

설치 버튼이 비활성이면 `Premiere 버전 확인 필요`, `이 PC용 설치 파일 없음`처럼 이유를 바로 옆에 표시한다. 네트워크 오류만으로 영구 경고 배너를 띄우지 않는다. 업데이트 진행 화면의 Escape는 설치 취소가 아니며, 교체 중에는 닫혀도 독립 관리자가 완료·복구를 담당한다.

정확한 상태·전역 중단·파일 교체·복구 기준은 [배포·업데이트 상세](distribution-and-updates.md)를 따른다. 실제 UXP 패널과 독립 업데이트 창 모두 좁은 폭·높은 화면 배율·긴 변경 내용·키보드 포커스·실패 상태를 검수한다.
