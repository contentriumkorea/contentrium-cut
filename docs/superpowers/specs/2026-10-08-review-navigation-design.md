# Contentrium CUT 반복 개선 1회차

사용자는 기획 → 설계 → 구현 → 검증 → 배포의 반복 진행을 승인했다. 기존 단일 패널과 모노 스튜디오 디자인 안에서 검토 동선을 개선한다. 컴퓨터유즈 금지와 새 공개본의 임의 재설치 금지는 유지한다.

## 기획

롱폼의 모든 컷을 한 번에 DOM에 쌓는 현재 목록은 원하는 카메라와 선택 이유를 찾기 어렵다. 컷 검토를 50개 단위로 나누고 카메라·선택 이유 검색을 제공한다. 필터는 표시만 바꾸며 원본 EditPlan, 적용 범위, 컷 수, 서명/해시는 바꾸지 않는다.

## 설계와 수용 조건

- 검토 화면에 카메라 필터, 선택 이유 검색, 표시 범위/전체 일치 개수와 이전·다음 이동을 제공한다. 한 번에 최대 50개의 컷 행만 만든다.
- 필터 변경은 첫 페이지로 이동한다. 빈 결과, 마지막 페이지, 계획 변경 시 페이지 범위를 처리한다. 원본 컷 객체와 배열은 변경하지 않는다.
- 필터링된 컷을 눌러도 그 컷의 원래 시작 프레임으로 이동한다. 기존 requireCurrent·업데이트 중단·인증 보호를 유지한다. 필터가 실제 적용 계획을 축소하지 않는다.
- 낮고 좁은 패널에 맞춰 외곽 여백·헤더 높이·리스트 배치를 줄이고 검색/페이지 컨트롤을 줄바꿈한다. 웹 전용 레이아웃·가상 DOM·새 외부 프로그램은 도입하지 않는다. 실제 UXP 외형은 미검증으로 기록한다.
- 반복 배포 뒤에도 기존 0.1.0 → 고정 v0.1.1 소스 보조 복구가 가능해야 한다. 전용 도구의 transport만 latest 조회를 고정 tag 조회로 바꾸고 If-None-Match를 제외한다. 일반 제품 업데이트는 latest를 계속 사용한다. 서명·release ID·정확한 commit·교체 직전 재검증·원본 보존은 기존 updater가 수행한다.

## 실행 순서

실패 회귀를 먼저 실행하고 UI 표시/탐색 및 고정 복구 조회를 구현한다. 관련 시험과 전체 시험, 독립 소스 검수를 통과한 뒤 0.1.2 패키지를 만든다. 실제 배포 바이트의 실행·구성/모델 해시와 공개 서명·재다운로드 해시를 검증한다. PC 설치본은 갱신하지 않는다. 실제 Premiere·설치 전환·Community-1 품질을 완료로 간주하지 않는다.
