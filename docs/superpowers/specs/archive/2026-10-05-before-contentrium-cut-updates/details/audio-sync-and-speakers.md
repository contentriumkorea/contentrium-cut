# 로컬 오디오·자동 싱크·화자 분석 상세 설계

상태: 상세 설계. 제품 구현·모델 설치·Premiere 적용 시험 결과가 아니다. 실제 호스트에서 검증된 범위만 지원 범위가 된다.

## 1. 확정 요구와 제안의 구분

확정 요구: 프로젝트 파일 자동 싱크 또는 기존 일반 트랙 시퀀스에서 시작, 분리·혼합 녹음 지원, 사용자 화자–카메라 연결, 원본 미디어·시퀀스·오디오 보존. 1배속만 처리하고 겹말은 복수 화자로 유지한다. ASR는 기본 컷에 필요하지 않으며, 사람별 음원 복원(source separation)은 하지 않는다.

엔진·분석 창·컷 유지 시간·싱크 허용 오차는 제안값이며 사용자 확정이나 실측 성능이 아니다. 자동 싱크는 오프셋만 계산하며 드리프트를 위한 속도 변경·시간 늘이기는 하지 않는다.

## 2. 엔진과 책임

| 역할 | 제안 후보 | 담당 범위와 경계 |
| --- | --- | --- |
| 미디어 조사·PCM 준비 | FFmpeg/ffprobe | 소스 스트림·채널·시간 정보를 읽고 분석 사본 생성 |
| 분리 채널 음성 활성 검출 | Silero VAD 공식 ONNX 모델 + CPU ONNX Runtime | 음성 존재 구간만 검출. 사람 식별·누음 제거는 별도 정책 |
| 혼합 녹음 화자 구간 | pyannote Community-1 | 세션 안의 화자 구간과 복수 화자 상태 반환 |
| 싱크 계산 | 다중 창 특징 비교 + 정규화 상호상관 | 공통 소리의 상대 시간 차이·후보 충돌·잔여 오차 기록 |
| 컷 결정 | 별도 공통 편집 계획기 | 카메라 가용성·최소 유지·끼어들기 규칙 적용 |

Silero는 8/16 kHz·ONNX·MIT를 공식 안내한다. ONNX 단독 경로에는 입출력·후처리 어댑터가 필요하며 기본 Python 패키지는 PyTorch 의존성이 있다. 한국어 적합성은 별도 시험한다. [Silero 공식 저장소](https://github.com/snakers4/silero-vad)

Community-1은 16 kHz 모노를 사용하고 다채널 입력을 평균해 모노로 만든다. 따라서 분리 마이크 묶음을 그대로 넣지 않는다. 공식 문서는 CPU·CUDA, 화자 수 지정, 일반·exclusive 출력, 오프라인 실행을 안내한다. 이 설계는 일반 출력인 speaker_diarization을 사용한다. [공식 모델 카드](https://huggingface.co/pyannote/speaker-diarization-community-1)

## 3. 입력 식별과 시간 계약

작업·촬영 세션·Premiere 항목 ID, 파일 크기·수정 정보·내용 식별값, 스트림·채널 번호를 기록한다. 같은 파일의 여러 클립 인스턴스와 배치는 따로 유지한다. 파일 변경·재연결 시 분석 캐시를 재검사한다.

시퀀스는 클립 시작·끝, 소스 In/Out, 속도, 활성 상태, 채널 매핑, 분석 범위를 갖는다. 파일은 카메라 묶음, 기준 녹음, 싱크·분석·최종 재생 채널을 따로 지정한다. 다른 녹음기의 시작점을 같다고 가정하지 않는다.

시간 표현은 세 계층으로 분리한다.

- 소스: 디코딩한 PCM의 원점과 정수 샘플 인덱스, 샘플레이트. 컨테이너 PTS·스트림 시작점·디코더 지연을 포함한 대응 정보를 유지한다.
- 공통 시간: 시퀀스 또는 싱크 세션의 ticks. JSON에서는 10진 정수 문자열로 전달한다. 표시용 타임코드와 내부 영점을 혼동하지 않는다.
- 편집: FPS를 분자/분모로 저장하고 구간은 [시작 프레임, 끝 프레임)으로 표현한다. 29.97 같은 근사 소수를 반복 누적하지 않는다.

1배속은 소스 시간 = 소스 In + 시퀀스 시간 − 클립 시작이다. 파일 싱크는 세션 시간 = 소스 시간 + 오프셋이다. 음수 위치를 없애려고 시작점을 옮기면 모든 소스에 같은 이동량을 적용하고 기록한다.

PCM 경계는 샘플 단위로 보관하고 컷을 만들 때만 가장 가까운 프레임으로 양자화한다. 정확히 중간이면 뒤 프레임을 택한다. 인접 구간의 공통 경계는 한 번만 변환하며, 충돌한 경계·0프레임 구간을 검출한다. 영상 배치의 반올림 오차와 음성 추정 오차를 분리해 표시한다. 오디오의 프레임 이하 배치 지원은 Premiere에서 검증된 경우에만 사용한다.

## 4. 분석 사본과 오디오 보존

분석용 16 kHz 모노는 사본이며 재생 오디오의 채널·게인을 바꾸지 않는다. 채널별 사본과 용도를 연결한다. ffprobe의 스트림·패킷·타임코드 정보만으로 실제 동기화를 증명하지 않는다. [ffprobe 공식 문서](https://ffmpeg.org/ffprobe.html)

분석 시간축은 실제 배치와 같은 길이로 만든다. 클립 사이 공백은 시간 길이를 유지하며, 없는 미디어를 무음 녹음과 구분하는 유효 구간 표식을 둔다. 동시간대 소스는 지정 채널·우선순위로 선택하고 임의 합산하지 않는다. 스테레오는 역상·서로 다른 대화 채널 여부를 검사한 뒤 모노를 결정한다.

기존 시퀀스에서는 선택한 소스 채널을 분석한다. Premiere 트랙 효과·마스터 믹서가 반영된 최종 출력이라고 표시하지 않는다. 분석 전처리의 정규화·대역 제한은 사본에만 적용하고 출력 오디오로 교체하지 않는다. 파일 경로에서 현장음은 싱크 근거로 사용하되, 사용자가 최종 재생용으로 선택하지 않았다면 중복 재생시키지 않는다.

중첩 내부, 1배속 이외 속도, 타임리맵, 불명확한 프록시 시간 대응은 적용 전에 차단한다. 가변 프레임레이트도 실제 PTS와 Premiere 표시 프레임의 대응이 검증되기 전에는 지원한다고 선언하지 않는다. 자동 재인코딩으로 조용히 우회하지 않는다.

## 5. 자동 싱크 판단

### 5.1 타임코드와 파형의 우선순위

사용자가 공통 시계로 기록했다고 확인한 타임코드는 배치 후보가 된다. 프레임레이트, 드롭프레임 여부, 날짜·자정 경계, 리셋·중복값을 검사한다. 시간 코드 숫자 차이를 단순 초 차이로 해석하지 않는다. 가능한 경우 공통 오디오와 대조하고, 둘이 충돌하면 한쪽을 자동으로 우선하지 않는다. 공통 음성이 없으면 “타임코드 기준, 음성 교차검증 없음”으로 표시한다.

파형 방식은 기준 녹음의 유효 구간과 각 후보의 공통 부분을 찾는다. 분석 사본의 에너지·스펙트럼 변화로 오프셋 후보를 좁힌 뒤, 후보 주변 PCM 상호상관으로 위치를 세밀하게 비교한다. 최고 상관 봉우리 하나를 정답 확률로 해석하지 않는다. [SciPy 공식 correlate 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.correlate.html)

### 5.2 채택 조건과 근거

한 파일의 시작·중간·끝에 분산된 유효 창에서 후보를 비교한다. 최초 제안은 10~30초 비교 창과 3개 이상의 분산 지점이며, 짧은 클립은 가능한 근거가 적다는 사실을 표시한다. 음성·비반복 소리의 유효 길이, 최고 후보와 경쟁 후보의 차이, 창별 시간차 일관성, 겹치는 길이, 디코딩 오류를 함께 평가한다. 무음 창, 지속 잡음만 있는 창, 반복 음악의 동등 후보는 자동 채택 근거에서 제외한다.

자동 채택은 단일 오프셋으로 여러 검증 지점이 일치할 때 허용한다. 검증 샘플의 잔여 오차가 1프레임 이하인지 확인하는 것은 설계 시험 목표이며 모든 입력의 정밀도 보장이 아니다. 검증하지 못한 구간을 “오차 0”으로 채우지 않는다. 결과에는 추정 오프셋, 실제 배치 오프셋, 창별 잔여 오차, 경쟁 후보, 채택·검토·미정 상태를 남긴다.

분리 마이크의 싱크는 공통 소리가 충분한 채널을 사용한다. 발화가 거의 없는 채널로 확정하지 않는다. 임시 합성 참조는 채널별 근거 검사 후 만들며, 원본 마이크로 저장하거나 화자 판별에 재사용하지 않는다.

### 5.3 분할 파일과 드리프트

각 파일 조각은 독립된 노드, 검증된 겹침은 상대 오프셋 관계로 기록한다. 기준과 직접 겹치지 않는 조각은 다른 검증된 노드를 통해 연결할 수 있으나, 누적 불확실성과 경로를 함께 기록한다. 여러 연결 경로의 합이 모순되거나 기준과 연결되지 않은 묶음은 미정 상태다. 파일명·생성일·연속 번호로 촬영 공백을 없애지 않는다.

시간별 잔여 오차로 드리프트를 검출한다. 진단용 기울기를 속도 보정으로 적용하지 않는다. 급격한 변화는 녹화 중단·손실·타임코드 리셋 후보로 표시한다. 구간 분리·기준점 확인 전에는 해당 파일을 컷 편집에 넘기지 않고, 사용자 제외나 수동 확인 없이 누락하지 않는다.

## 6. 분리 마이크 분석

마이크 채널과 사람 연결은 사용자가 확인한다. 마이크 교체·파일 분할은 구간별로 연결한다. 복사 채널은 분리 모드의 근거가 될 수 없다. 여러 비무음 구간의 파형·에너지 변화가 상수 게인 또는 극성 반전 관계로 거의 같으면 중복 후보로 알린다. 높은 상관만으로 채널을 삭제하지 않는다. 누음도 비슷하게 보일 수 있다.

Silero VAD로 각 채널의 음성 활성 구간을 얻고, 채널별 잡음 바닥·음성 레벨·클리핑·결손 여부를 계산한다. 발화가 적은 채널의 최대값을 강제로 다른 사람과 같게 만드는 단순 전체 정규화는 피한다. 보정 기준은 사람이 단독으로 말하는 예시에서 얻고, 부적합하면 사용자가 다른 예시를 선택한다. 마이크를 옮기거나 자동 게인 특성이 바뀐 구간은 이전 보정의 유효성을 재검사한다.

누음 판단은 “활성 채널 수 = 화자 수”로 처리하지 않는다. 단독 예시에서 화자별 상대 마이크 레벨 패턴을 얻는다. 여러 채널의 활성 시작·끝이 같고 한 화자의 누음 패턴으로 설명되면 한 사람 후보로 묶는다. 둘 이상의 채널에 그 패턴으로 설명되지 않는 음성 활동이 지속되면 겹말 후보로 남긴다. 유사 레벨·강한 잔향·마이크 공유 때문에 분리가 불가능하면 미확정으로 표시한다.

VAD 점수·잡음 대비 레벨·채널 차이·누음 패턴은 별도 근거이며 가중합을 “정확도 98%”로 표시하지 않는다. 시작·종료 임계값과 우세 기준은 한국어 샘플에서 조정한다. 화면에는 음성 약함·누음 의심·복수 발화의 사유를 보여주고, 혼합 모드 전환은 사용자에게 맡긴다.

## 7. 혼합 녹음과 세션 화자 ID

혼합 모드는 한 녹음의 발화 시간에 화자 표식을 붙인다. 단독과 동시 발화를 구별하고 일반 diarization의 중첩을 유지한다. exclusive 출력이나 “가장 긴 화자 하나”로 덮어쓰지 않는다.

화자 수는 추정하거나 사용자의 선택 힌트를 받는다. 화면 밖 목소리·추가 출연자가 있을 수 있으므로 지정 인원과 결과가 충돌하면 검토 사유를 남긴다. 별도 신뢰도 필드가 없는 출력에 임의 점수를 추가하지 않는다.

세션 임시 ID마다 떨어진 단독 예시로 이름·카메라를 연결한다. 겹말을 대표 예시로 택하지 않는다. 같은 사람의 중복 ID는 병합, 섞인 사람은 구간 재지정으로 수정한다. 화면 밖 화자도 대체 카메라를 명시 연결하되 해당 카메라의 실제 등장 인물 집합에 추가하지 않는다.

이름은 표시명이다. 다른 세션의 번호·이름·비슷한 음색으로 사람을 자동 동일시하지 않는다. 매핑 템플릿도 현재 세션 예시 확인 후 활성화한다.

### 긴 녹음의 청크 연결

자원이 허용되면 세션 전체를 하나의 화자 군집화 범위로 처리한다. 메모리 때문에 외부 청크를 나누는 경우, 청크 ID·세션 시작 샘플·원본 범위·겹침 문맥·모델 버전을 저장한다. 각 청크의 SPEAKER_00은 독립 ID다. 세션 전체 인원 수를 모든 청크에 강제로 적용해 실제로 없는 사람을 만들어내지 않는다.

인접 청크의 겹침 문맥에 공통 단독 발화가 있으면 동일한 실제 구간에 붙은 지역 ID들을 연결 후보로 만든다. 내부 번호나 등장 순서로 연결하지 않는다. 단독 발화 임베딩 비교가 추가로 필요하면 고정한 모델의 검증된 추출 인터페이스와 버전을 사용하며, 공개 결과에 임베딩이 있다고 가정하지 않는다. 공통 발화가 없거나 후보가 비슷하면 연결을 미정으로 두고 사용자 예시 확인으로 해소한다.

겹치는 문맥은 경계 판별에 사용하고 최종 구간은 청크 중심 영역에 한 번만 귀속한다. 경계의 화자·겹말 충돌은 검토 구간으로 보존한다. 지역 ID → 세션 ID → 사용자 이름·카메라의 연결표와 변경 이력을 저장하고, 재분석으로 ID가 바뀌면 이전 카메라 연결을 자동 승계하지 않는다.

## 8. 공통 분석 결과와 컷 정책 연결

분석기는 시간별 증거를 제공하며 카메라 선택·짧은 발화 억제·최소 길이 예외를 결정하지 않는다. 필수 결과는 작업·세션·분석 버전, 시작·끝 ticks, 원래 샘플 경계, 확인된 활성 세션 화자 집합, 판별 불가 상태와 사유, 유효 오디오 범위, 근거·입력 식별값이다. 원시 결과와 사용자 교정은 분리한다.

겹말은 각 시작·종료 경계에서 참여자 집합을 갱신한다. A+B에서 B+C로 바뀌는 구간을 A+B+C라는 한 집합으로 뭉개지 않는다. 편집기는 그 시점의 모든 확인된 참여자를 실제로 담는 WIDE/투샷인지 검사한다. 대체용으로 연결한 카메라가 실제 그 사람을 담는다고 추정하지 않는다.

상태는 단독·복수 발화, 확인된 비발화(silence), 정상 입력의 판별 불가(unknown), 입력 누락(missing_audio)으로 구분한다. unknown은 별도 사람 ID가 아니라 구간 상태다. 후보 화자·채널 충돌·청크 연결 충돌 같은 근거를 함께 기록한다. 확인된 A와 판별 불가 활동이 함께 있으면 두 정보를 보존하며 unknown을 가짜 두 번째 사람으로 세지 않는다. 모델이 실패하거나 필수 음원이 없으면 unknown/silence로 바꾸지 않고 적용을 차단한다. 원래 오디오 공백은 배치대로 보존하되 확인된 침묵으로 위장하지 않는다.

선택 범위의 sessionSpeakerId에 필수 카메라 연결이 없으면 SPEAKER_MAPPING_REQUIRED로 차단한다. 정상 분석 후에도 특정 구간의 화자 배정만 불확실한 경우에 한해 unknown-hold를 사용한다. 미매핑 ID를 unknown으로 이름만 바꾸어 차단을 우회하지 않는다. 청크 연결 미정도 임시 ID의 필수 연결 문제인지 국소 구간 판별 불가인지 구별한다.

결정 순서·시작 화면·영상 대체·수동 고정·최소 길이 예외는 [편집 정책과 검증 계약](editing-policy-and-qa.md)의 단일 규칙을 따른다. 순서는 지원·커버리지 관문 → 유효한 수동 고정 → unknown → 지속 겹침 → 짧은 경쟁 발화 → 단독 발화 → 침묵/지속 기준 미만 겹침이며 일반 전환에 최소 길이를 적용한다. 본 문서에서 다른 우선순위를 정의하지 않는다.

초기 제안은 M=2초, 경쟁 발화 길이 ≤B=0.6초 억제, 연속 겹침 길이 ≥O=0.8초다. 실제 길이는 정책 문서의 프레임 정렬·임계값 올림 후 판정한다. 음성 분석기가 짧은 구간을 미리 삭제하거나 unknown·침묵을 끼워 겹침 길이를 늘리지 않는다. 판별 대기시간은 컷 지연이 아니며 종료된 화자에게 예약 컷을 만들지 않는다. 컷 설정만 변경하면 분석 캐시는 재사용한다.

## 9. 런타임·모델·비공개 처리

CPU 경로를 기본으로 두고 CUDA 호환성과 메모리가 확인되면 GPU를 선택한다. CPU 전환·재시작을 표시하며 최소 사양·최대 길이·처리 시간은 실측 전 확약하지 않는다. 전체 PCM을 RAM에 강제 적재하지 않고 디스크·디코딩 범위·모델 메모리를 검사한다.

모델 상태는 미설치·다운로드·파일 확인·사용 가능·오류로 구분한다. 버전·해시·출처를 고정하고 일부 다운로드를 완료로 표시하지 않는다. Community-1 초기 접근에는 사용자 본인의 Hugging Face 조건 동의와 토큰이 필요하다. 필요한 저장소의 읽기 권한만 부여하고 토큰을 프로젝트·분석 JSON·로그에 저장하지 않는다. [Hugging Face 토큰 안내](https://huggingface.co/docs/hub/security-tokens)

모델 가중치의 CC-BY-4.0과 pyannote.audio 코드의 MIT를 구분하여 고지하고, 실제 배포에 포함할 각 의존성·FFmpeg 빌드의 라이선스와 귀속 정보를 별도로 기록한다. 모델 설치 승인과 외부 음성 업로드 동의를 같은 것으로 취급하지 않는다. 기본 분석에서 음성·영상·대표 발화·임베딩은 외부에 전송하지 않는다.

pyannote의 선택적 telemetry는 분석 프로세스 범위에서 비활성화하고 실제 네트워크 관찰로 검증한다. 모델 다운로드가 끝난 뒤 네트워크가 끊긴 상태에서도 필요한 분석이 가능한지 확인한다. 실패 시 클라우드로 자동 우회하지 않는다. [pyannote 공식 telemetry 안내](https://github.com/pyannote/pyannote-audio#telemetry)

취소는 안전한 작업 경계에서 처리하고 중단 결과를 완료 캐시로 등록하지 않는다. 같은 입력·모델·설정의 완료 부분만 재사용하며 중간 재개 미지원 단계는 다시 수행한다. 원본·완료 시퀀스는 캐시 정리로 삭제하지 않는다.

## 10. 평가와 실제 검증의 경계

한국어 평가 자료는 단독·겹말·누음·작은 목소리·짧은 답변·웃음·침묵·복사 채널·손실을 구분한다. 설정 조정 자료와 평가 자료를 분리하고 공개 벤치마크를 사용자 녹음의 정확도로 옮겨 쓰지 않는다.

화자 평가는 음성 누락·오검출·사람 혼동, 겹말 검출, 화자 수 오류, 청크 연결 오류를 나누어 기록한다. DER을 사용하면 겹말 포함 여부, 경계 허용 구간, 평가 범위를 함께 명시한다. 전체 DER 하나로 카메라 편집 품질을 대체하지 않는다. [pyannote.metrics 공식 평가 문서](https://pyannote.github.io/pyannote-metrics/reference.html#diarization)

편집 평가는 오인 화면 지속 시간·짧은 컷·전환 누락·겹말 대체·수동 수정량을 본다. 정책에 맞는 유지를 분석 오류로 세지 않는다. 싱크는 알려진 기준점의 오프셋·잔여 오차·장시간 누적 변화와 잘못된 자동 채택을 분리해 평가한다.

“발화 없음”은 정상 입력·정상 분석에서만 허용한다. 오류에는 해결 상태·재시도 위치를 표시한다. 오디오 보존은 구조 비교·Premiere 재생으로 확인하고, 동일 효과 렌더 경로가 검증된 경우 렌더 비교를 추가한다.

공식 자료는 도구의 입력·출력·실행 기능을 뒷받침한다. 다중 창 싱크·누음·청크 연결·Windows 성능·Premiere 시간 적용과 오디오 보존은 설계와 검증 조건이며 구현·실측 완료가 아니다.
