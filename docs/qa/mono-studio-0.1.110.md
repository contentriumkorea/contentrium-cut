# Contentrium CUT 0.1.110 설치·배포 기록

2026-10-19 사용자 요청: 재설치 → 배포 → 검증. 반복 자동화 재개 요청이 아닌 단일 작업이다.

사용자가 이어서 “진행”으로 순서 조정을 승인했다. 아래 보류 기록은 이전 체크포인트이며, 현재는 배포 → 재설치 → 검증으로 진행한다. 기존 대기 작업은 정상 복구 경로로만 처리하고, 실제 패널 첫 연결 증거를 대신 만들지 않는다.

## 변경과 사전 확인

- [Mono Studio 05 단일 작업 화면](mono-studio-workbench.md)의 검증된 변경을 0.1.110으로 패키징한다. 기존 공개 0.1.109 파일을 덮어쓰지 않는다.
- 시작 공개 상태: 정식 110개, 첨부 558개. 최신 공개 버전은 0.1.109이며 고정 v0.1.1 접근을 유지한다.
- 등록된 실제 설치본은 0.1.107, Premiere는 종료 상태다. 기본 폴더의 별도 잔존본과 등록된 설치 위치를 구분했다. 실제 등록 경로·설정 및 기존 복구 기록의 원본은 비공개 로컬 증거에 보존한다.
- 기존 업데이트는 0.1.0 → 0.1.107의 `PENDING_ACTIVATION`, 첫 패널 연결과 비공개 설치 연결이 완료되지 않은 상태다. 완료 영수증을 만들거나 보호 상태를 임의로 해제하지 않는다.
- 설치기/업데이터는 미공개 초안을 설치 대상으로 허용하지 않는다. 새 정식 버전 공개가 설치보다 먼저 필요하여 사용자에게 배포 → 재설치 → 검증 순서 조정을 질문했다. 답변 전 공개·재설치 실행은 보류한다.
- 순서를 조정하더라도 기존 대기 작업은 검증된 복구 경로로 처리해야 한다. 실제 패널 등록 위치 확인·활성화는 사용자 직접 Premiere 패널 연결이 필요하며 컴퓨터유즈·Premiere 조작 금지는 유지한다.

## 검증과 보존

- 원래 UI 변경의 Node 789개, Python 정책/구조 56개, 추출 패키지 핵심 핸들러 10개 통과 기록을 유지한다.
- 이번 배포 준비의 설치·업데이트·배포 관련 Python 회귀 175개 통과. 새 diff의 비밀정보·개인 사용자 경로 검사 0건.
- 기존 공개 릴리스/첨부 메타데이터, 실제 설치의 대기 작업 원본과 모델 해시를 로컬 `.superpowers/mono-release-0.1.110/`에 보존한다. 이 폴더는 공개하지 않는다.
- 빌드 성공이나 CLI 시험을 실제 설치·Premiere 시각/편집 검증으로 표시하지 않는다. Community-1 실제 사람 화자 품질도 미검증이다.

## 빌드·검증 결과와 종료 체크포인트

- 5파일 생성 완료: 온라인 설치기 16,958,152바이트, 전체 Setup 93,437,783바이트, 본체 ZIP 332,237,081바이트, 패널 CCX 87,617바이트, 압축형 수동 구성 332,687,580바이트.
- [실행 파일 진입점·아이콘 검사](installer-0.1.110-proof.json): 실제 frozen Setup 29개/온라인 5개 모듈과 소스 일치, 두 진입점 일치, PE 아이콘 7개 및 창 PNG 일치. 온라인 파일은 공개 최신 0.1.109를 발견하고 서명을 검증했다. 전체 Setup의 격리된 읽기 전용 진단은 0.1.110/exit0, 설치 변경 없음이다.
- [본체·패널 검사](package-0.1.110-proof.json): 실제 frozen 본체 29개 모듈·진입점 일치, CCX 16파일 일치, 압축 CRC 및 같은 버전 구성 확인. 새 임시 폴더에 추출한 본체 `--probe`가 `runtimeReady=true`, 0.1.110으로 종료했다. 실제 새 CCX에서 추출한 패널 핵심 시험 10개도 통과했다. 압축형 구성은 기존 빌더의 검증을 통과했다.
- 최초 위치 점검 도우미는 기본 폴더와 등록된 실제 폴더가 같다는 가정 때문에 assert 실패했다. 등록된 명령을 실행하지 않고 정확히 파싱해 실제 위치를 확인하고, 그 위치의 자료·모델·복구 기록을 보존했다. 제품 설치가 실패한 것으로 해석하지 않는다.
- 독립 읽기 전용 검수도 현재 설치에 대한 일반 재설치 CLI로 첫 연결 대기를 건너뛸 수 없음을 확인했다. 기존 first-install 복구는 원래 정확한 번들만 수리하며, 미완료 업데이트는 새 설치 시작을 차단한다. 저수준 설치 훅 직접 호출, 상태 초기화, 활성화·매핑 영수증 조작은 수행하지 않았다.
- [종료 보존 확인](mono-studio-0.1.110-preservation.json): 기존 공개 110개/558첨부, 실제 설치의 중요 메타데이터 6파일·모델·작업 자료 해시 불변. 설치 0.1.107/공개 최신 0.1.109 유지. 새 릴리스 생성·업로드·서명 문서 생성·사용자 설치 교체 없음.
- 종료 단계: 로컬 0.1.110 빌드·패키지/CLI 검증 완료. 순서 조정 질문은 미응답이며 공개·재설치는 보류다. 다음에는 그 답변과 실제 첫 연결 대기 복구 조건을 확인한 뒤 기존 결과물로 이어간다. 중복 빌드나 새 버전 증가는 필요 없다. 실제 설치·Premiere 화면/편집·Community-1 품질은 미검증이다.

- 사용자의 “진행”에 따라 배포 → 재설치 → 검증으로 이어갔다. 기존 빌드 5개와 최종 시험 입력 7개의 해시를 재확인했고, 공개 대상 22파일의 개인 경로·인증정보 패턴 검사는 0건이었다. 소스 커밋 `42c4de8c9bb6985b7ee36d708d6f388a3f4c44f3`을 main에 반영했다.
- [v0.1.110](https://github.com/contentriumkorea/contentrium-cut/releases/tag/v0.1.110)을 제목 **Contentrium CUT**, release `416890743`, 첨부 9개로 공개했다. 기존 게시물·자산을 교체하거나 숨기지 않았다. 기존 110개 릴리스/558개 자산의 제목·공개 상태·대상·본문·다운로드 URL·ID·크기·해시가 불변이며 현재 111개/567개다.

- 로컬 검증 도우미 첫 실행은 모듈 검색 경로 누락으로 각각 `contentrium_cut`, `tools` import에서 중단됐다. 설치 변경 전에 발생했으며 프로세스 한정 PYTHONPATH를 보완한 뒤 정상 재실행했다. 제품 오류로 분류하지 않는다.

## 실제 재설치의 현재 경계

- 두 native 소유권 lease와 Premiere 종료를 확인하고, 기존 107의 서명된 대기 자산 해시·복구 snapshot·설치 파일·Adobe 등록을 검증했다. 기존 journal은 정상이며 디스크의 `PENDING_ACTIVATION`을 새 프로세스가 `RECOVERY_REQUIRED`로 다루는 보호 동작을 확인했다.
- 독립 리뷰에서도 107의 미완료 `PENDING` 준비를 남긴 채 110으로 바꾸면 `INSTALL_ENROLLMENT`로 차단됨을 확인했다. rollback 후 새 설치도 이 준비 상태를 해결하지 못하므로 실행하지 않았다. 기존 migration CLI는 고정 0.1.1 전용이며 변경하지 않았다.
- 정확한 기존 107의 공개 서명 대상과 자산을 다시 확인하고 기존 `prepare_installation()`을 호출했다. 결과는 **PENDING_PROVISIONING / OPEN_PREMIERE_PANEL**이다. 만료된 동일 버전 연결 challenge만 정상 갱신했으며 updater journal·기존 코드·Adobe 등록·활성화 gate는 바꾸지 않았다. 이 호출 경계에 대한 독립 검수에서도 중요 문제가 없었다.
- [보존 확인](mono-studio-0.1.110-preservation.json): 모델·작업 자료와 중요 메타데이터 5파일 불변. 예상 변경은 `updates/install-preparation.json`의 동일 107 연결 준비 갱신이다. 기존 준비 원본·복구 기록·실패 증거는 비공개 로컬 증거에 보존한다.
- 사용자가 실제 설치된 Premiere의 Window → UXP Plugins → Contentrium CUT 패널을 한 번 열어 실제 폴더 연결 영수증을 생성해야 다음 준비·활성화와 110 교체를 진행할 수 있다. 컴퓨터유즈/Premiere 직접 실행·조작·종료 금지 때문에 이 동작을 대신하지 않았다. 사용자에게 실제 패널 열기를 요청했다.
- 종료 경계: **0.1.110 공개·공개 검증 완료, 이 PC 설치는 0.1.107 유지, 0.1.110 재설치 미완료**. 다음은 동일 107 첫 연결을 실제 증거로 마친 뒤 정식 110 업데이트다. 영수증·handoff·완료 상태를 만들거나 보호를 해제하지 않는다. 실제 설치 전환·UXP 시각/편집·Community-1 품질은 미검증이고 반복 자동화는 PAUSED 유지다.
