# Contentrium CUT — 단일 Premiere 패널 재설계

2026-10-06. 사용자가 지적한 제품 방향을 반영한 0.1.1의 필수 조건이다. 기존 오디오·편집·보존·업데이트 설계를 유지하고, 별도 프로그램과 수동 연결을 전제로 한 사용 흐름을 대체한다. 구현·설치·배포 및 2·3차 검수는 이미 승인된 범위이다.

## 제품 경험

사용자는 Premiere에서 Contentrium CUT 패널을 열고, 현재 타임라인의 트랙 역할을 지정하고, 화자를 분석한 뒤 컷을 검토·적용한다. 별도 창, 연결 코드, 로컬 엔진 실행, 모델 관리 앱 이동을 정상 사용 단계로 요구하지 않는다. 무거운 분석은 숨겨진 로컬 프로세스가 수행하지만 모든 제어와 상태는 이 패널 안에 있다.

결과는 Premiere에서 계속 수정할 수 있는 일반 시퀀스다. 패널의 컷 구간을 선택하면 Premiere 재생 헤드가 그 위치로 이동한다. 원본 시퀀스, 미디어, 선택하지 않은 오디오와 보호 트랙의 보존 기준은 기존 설계를 따른다.

2026-10-06 사용자 추가 확정: 사용할 소스는 구간별 실제 영상 클립으로 분할하고, 결과 시퀀스의 **모든 영상 트랙 중 최상단**에 새 `Contentrium CUT` 트랙 하나로 정렬한다. 각 컷은 원본 소스와 In/Out을 유지하여 직접 이동·트리밍할 수 있어야 한다. 렌더 파일이나 중첩·멀티캠 결과로 대체하지 않는다. 임시 작업은 이 트랙의 시퀀스 끝 이후에서 수행하고 완료 시 해당 임시 조각만 제거하여 위에 빈 작업용 트랙을 남기지 않는다. 선택 범위 밖의 기존 카메라 조각은 원래 트랙·시간을 유지한다.

자막은 별도 자막 트랙을 사용하며 이번 영상 컷 정리 기능의 수정 대상이 아니다. 로고·그래픽 배치 및 추가 편집은 사용자가 직접 한다. 기존 비카메라 트랙의 클립·효과·시간은 변경하지 않지만, 새 컷 트랙을 최상단에 놓으므로 로고와의 최종 합성 순서를 자동 보정하거나 기존 화면 합성을 동일하게 보장하지 않는다. 이 결정은 이전의 ‘카메라 중 최상단/상단 오버레이 유지’ 출력 배치 제안보다 우선한다.

## MVX 참조와 시각 원칙

참조: [PxlSafe MVX AI](https://www.pxlsafe.com/mvxai), [공식 설치·워크스루](https://www.pxlsafe.com/mvxai/docs). 공식 워크스루의 Project, Cut, Finish 화면을 직접 관찰했다. 이는 데모 화면 관찰이며 MVX를 설치해 성능을 시험하거나 내부 구현을 확인한 것은 아니다.

관찰한 시각 요소를 Contentrium CUT에 적용한다.

- 세로로 도킹되는 조밀한 패널, 차콜 외곽 프레임, 어두운 안쪽 작업면.
- 둥근 모서리와 가는 상단 하이라이트로 표현하는 절제된 입체감.
- 한 단계의 작업을 한 화면에 표시하고, 하단의 주 실행 버튼은 고정한다.
- 작은 상단 브랜드와 메뉴, 절제된 밝은 글씨, 활성 상태만 구분하는 포인트.
- Contentrium CUT의 글자·아이콘·컨트롤은 직접 작성한다. 기능은 음악 비트가 아닌 트랙·화자 중심이다.

기본 도킹 폭 420px, 최소 폭 320px, 최소 높이 500px. 본문·입력·버튼은 13px 이상, 보조 메타데이터는 11px 이상. 320px에서도 가로 스크롤 없이 입력 가능해야 한다. 큰 빈 공간, 장식 통계 카드, 긴 단계 나열을 제거한다. 내용 영역만 스크롤하고 헤더·단계 이동·진행 상태·실행 버튼은 유지한다.

색상: 외곽 #25282b, 패널 #191c1f, 입력 #131619, 경계 #3b4045, 본문 #edf0f2, 보조 #a7afb6. 낮은 채도의 푸른 회색은 활성 컨트롤과 진행 표시만 사용한다. 대비와 포커스 표시를 우선하고 입체 그림자가 입력 영역을 흐리게 하지 않게 한다. UXP에서 지원하는 CSS만 제품 패널에 사용한다.

## 화면과 동작

상단에는 Contentrium CUT, 버전, 설정 메뉴를 둔다. 그 아래에는 실제 시퀀스 이름·시간·영상/오디오 트랙 수와 새로고침을 표시한다. 정상 연결은 작은 상태 표시로 충분하며 연결 설정 화면을 띄우지 않는다.

| 화면 | 주요 조작 | 하단 실행 |
|---|---|---|
| 트랙 | 실제 V1/V2/A1 이름, 카메라 역할, 보이는 화자, 분석 오디오·stream·채널, 녹음 방식, 적용 범위, 싱크 | 화자 설정으로 |
| 화자 | 로컬 분석, 감지 화자 이름과 카메라, 단독 발화 예시 듣기, 병합·구간 재지정·되돌리기, 누설음 보정 | 화자 분석 / 컷 설정으로 |
| 컷 편집 | 시작/예비 카메라, 최소 샷, 짧은 발화, 겹침 정책, 수동 고정 구간 | 편집안 만들기 |
| 검토 | 컷 목록·범위·카메라·이유, 검토 항목, 해당 위치 이동, 수동 수정, 원본 보존 안내 | Premiere에 컷 적용 |
| 설정 | 모델 설치·접근 권한, 분석 자원·캐시, 프로젝트 설정, 버전·업데이트·복구 | 해당 설정의 명시적 실행 |

설정 화면에서 돌아오면 이전 편집 단계와 입력값을 유지한다. 작업 중에도 상태/취소/업데이트는 접근 가능하다. 분석 결과가 없으면 검토 화면에는 정직한 빈 상태를 표시하고, 시연 수치나 가짜 파형을 실제 데이터처럼 표시하지 않는다. 미리보기용 fixture는 별도 QA 도구에서만 주입한다.

현재 타임라인은 패널 시작 시 자동으로 읽는다. 프로젝트나 시퀀스가 없으면 Premiere에서 시퀀스를 열라는 간단한 빈 상태를 표시하고, 프로젝트 패널에서 선택한 소스로 입력 시퀀스를 만드는 경로를 제공한다. 타임라인을 바꾸면 입력과 분석의 유효성을 다시 확인한다. 트랙 역할은 stable track/clip identity로 보관하고 다른 시퀀스에 잘못 이식하지 않는다. 분석 입력 변경은 분석·편집안을, 카메라/정책 변경은 편집안을 무효화한다.

저장한 분석·화자 교정을 다시 읽거나 컷을 실행하기 전에는 원본 내용이 같은지 확인한다. 파일 경로·크기·수정 시각이 같아도 내용이 달라졌으면 기존 분석을 사용하지 않는다. 큰 파일 검증은 취소 가능한 별도 작업으로 진행하고 패널에는 확인 중인 상태를 표시한다. 대기 중에도 연결 확인·취소·업데이트를 처리한다. 검증 결과를 받는 과정이 끊겨 실행 허가 여부가 불확실하면 컷을 자동 재실행하지 않고 기존 작업 기록으로 복구한다.

## 숨겨진 로컬 실행 구조

1. 단일 설치 프로그램이 검증된 패널과 로컬 런타임을 설치한다. 정상 사용 중 별도 GUI를 실행하지 않는다.
2. 사용자 계정의 시작 항목으로 등록한 경량 감독 프로세스가 Premiere 실행을 감지한다. 설치 직후에도 같은 프로세스를 숨김으로 시작한다. 무거운 모델은 분석 worker에서 필요할 때 로드한다.
3. 감독 프로세스는 서명/설치 영수증으로 확인한 활성 런타임만 실행한다. 명시적인 설치 루트 인자를 전달해 MSIX 리디렉션 등 환경 변수 차이로 다른 데이터 폴더를 만들지 않는다.
4. 반복 충돌은 제한된 backoff로 처리하고 재시도 횟수·오류를 패널이 읽을 수 있는 상태로 기록한다. 실제 Premiere 종료와 CUT 작업 종료가 확인돼야 idle 종료한다. 업데이트 작업은 패널이나 Premiere가 닫혀도 이어진다.
5. 자동 시작 시 UXP shell.openExternal/openPath를 호출하지 않는다. Adobe의 외부 실행 동의 창이 매번 뜨는 구조는 정상 경로로 부적합하다.

최초 설치에서는 파일 설치가 끝난 뒤 사용자가 Premiere의 Contentrium CUT 패널을 한 번 열어 연결 준비를 마무리한다. 설치 창은 그동안 응답하며 현재 필요한 단계를 안내한다. 이 단계에서 닫았다 다시 실행하면 같은 설치 대상의 연결 준비만 재개하고, 이미 설치된 패널을 다시 교체하지 않는다. 연결 코드 입력이나 폴더 선택은 요구하지 않는다. 연결·모델 준비와 자동 시작 등록이 끝나기 전에는 설치 완료로 표시하지 않는다. 이후 패널을 열 때는 이 설치 단계를 반복하지 않는다.

설치기는 기존에 등록된 검증된 설치 위치를 우선한다. 실행 환경의 기본 폴더가 달라졌다는 이유로 두 번째 설치를 만들지 않는다. 묶음 Silero 모델은 서명된 정확한 런타임에서 검증 후 준비하며, 유효한 기존 사용자 모델과 작업 데이터는 보존한다.

인증은 설치별 난수 비밀값으로 자동 초기화한다. 공개 CCX/소스/릴리즈에는 비밀값을 넣지 않는다. 설치 프로그램은 해당 사용자만 접근하는 CUT 인증 저장소와 해당 제품의 외부 UXP PluginData에 bootstrap을 배치한다. 패널은 UXP의 자기 data folder로 읽는다. 다른 플러그인 폴더나 일반 공유 위치를 인증 근거로 사용하지 않는다.

서버와 패널은 nonce·만료·일회성 증명으로 서로 확인하고, 이후에는 프로젝트 범위가 제한된 토큰을 사용한다. 잘못된 localhost 서버에 패널의 비밀값이나 미디어 경로를 전송하지 않아야 한다. HTTP Origin/Host 검증, request 크기 제한, 인증, epoch/host/bundle 일치 검사는 유지한다. bootstrap 누락이나 변조 시 권한을 낮추거나 인증을 생략하지 않는다. 패널에서 진단/복구 안내를 제공하고 정상 재설치로 복구한다.

설치 경로와 UXP 데이터 위치는 실제 설치·native 패널로 검증한다. 개발자 플러그인으로만 성공한 결과는 설치된 제품의 성공으로 간주하지 않는다.

## 모델과 업데이트

Silero와 Community-1의 준비/설치/오류 상태를 설정 안에서 관리한다. 제공자 조건 동의와 계정 접근 권한이 필요한 작업은 사용자가 수행한다. 토큰은 화면에서 마스킹하고 로그·작업 파일·브라우저 저장소에 남기지 않는다. 실제 모델이 없는 상태에서 모의 테스트를 실제 화자 분리 품질로 보고하지 않는다.

패널을 열 때 GitHub의 서명된 업데이트를 확인한다. 없으면 편집을 방해하지 않는다. 있으면 패널 안의 배너에 버전/변경 사항과 업데이트·나중에를 표시한다. 업데이트를 누르면 즉시 신규 CUT 작업을 막고 분석을 취소한다. 진행 중인 짧은 Premiere 트랜잭션은 반환을 확인한 후 다음 작업을 차단한다. 필요 시 프로젝트 저장과 Premiere 정상 종료를 안내하며 강제 종료하지 않는다. 숨겨진 업데이트 관리자는 다운로드·검증·설치·롤백·새 런타임 검증을 이어간다.

0.1.0 설치 오류를 고친 소스 보조 전환은 영수증에 사실대로 기록한다. 기존 공개 payload와 실패 journal을 덮어쓰지 않는다. 0.1.1부터 숨겨진 실행과 패널 제어를 포함해야 한다. 0.1.2는 공개만 하고 로컬 0.1.1은 유지한다.

## 완료 판정

- 설치된 패널을 열었을 때 별도 창/연결 코드/엔진 실행 버튼 없이 현재 타임라인이 표시된다.
- V/A 트랙의 실제 이름과 수가 맞고, 패널에서 역할·채널·카메라·싱크·컷 정책을 바꿀 수 있다.
- 네 단계와 설정의 입력 유지, 좁은 폭, 빈 상태, 취소, 오류 복구를 실제 UXP에서 확인한다.
- 패널의 구간 클릭이 실제 Premiere 재생 헤드를 이동시키고, 적용된 일반 시퀀스는 컷·오디오·효과·원본 보존 readback을 통과한다.
- Premiere 재시작, 패널 재열기, 엔진 비정상 종료 후 복구를 관찰한다. 준비 시간은 실측하며 목표치만으로 성공을 주장하지 않는다.
- 인증 bootstrap, nonce replay, 잘못된 서버, stale analysis, 중복 apply, 취소/업데이트 경합을 회귀 시험한다.
- 2차의 실제 설치와 native 확인이 끝나기 전에는 배포 완료로 표기하지 않는다. 3차는 별도 결함 검수/설계/수정/공개가 있어야 한다.
