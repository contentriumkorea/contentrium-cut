# 설치 진행·실패 안내와 아이콘 개선

사용자 보고: 다른 PC에서 0.1.108 온라인 설치기가 `설치 단계가 완료되지 않았습니다`만 표시한다. Premiere 종료 후에도 재현. 전달된 별도 문구는 `검증된 설치 창에서 계속해 주세요`라는 인계 안내이며 구체적인 오류 코드는 아직 없다. 따라서 Premiere 실행이 원인이라고 단정하거나 해당 PC 설치 성공을 주장하지 않는다.

목표는 기존 설치·복구 신뢰 경계를 보존하면서 실제 진행률, 읽을 수 있는 설치 단계, 오류 코드·해결 안내, 일관된 모노 디자인을 제공하고 Tk 기본 깃털 아이콘을 제거하는 것이다. 앞선 배포 작업의 수정 요청으로 설계→수정→검증→새 패치 공개까지 진행한다. 사용자 PC 재설치·컴퓨터유즈·브라우저 자동화·Premiere 조작·중단된 반복 자동화 재개는 제외한다.

## 설계

- 온라인/전체 Setup에 같은 UI를 사용한다. 660×540, 여백과 위계가 있는 검정/흰색 화면, 4단계 표시, 실제 byte 기반 진행 막대·받은 용량/전체·속도·남은 시간, 취소·재시도·오류 내용 복사. 검증/등록처럼 수치 측정이 안 되는 단계는 움직이는 막대로 표시하고 임의 퍼센트를 만들지 않는다. 정상 설치 완료와 패널 첫 연결 대기를 구별한다.
- 창 제목줄·EXE·작업표시줄에는 자체 단색 C 아이콘을 적용해 깃털을 없앤다. 리소스가 없는 소스 실행에는 투명 아이콘을 사용한다. 기존 원본 사진은 수정하지 않는다.
- GitHub/FFmpeg streaming transport에 선택적 byte 진행 콜백을 추가한다. 기존 호출은 호환 유지. 취소 시 다음 읽기·변경 경계에서 중단하고 원본/설정/실패 증거를 보존한다.
- 기존 등록 설치의 서명·코드 확인도 창을 먼저 연 뒤 worker에서 실행한다. 확인 전에는 설치/열기가 불가능하고, 확인 중 취소는 요청 상태를 표시한 후 검증 경계에서 종료한다.
- 온라인 설치기는 child Setup에 `--result`를 전달한다. 실패 시 숫자 종료 코드만 버리지 않고 검증된 결과의 오류 코드·안내를 유지한다. 읽기 전용 `--diagnose`로 child startup/위치 확인을 네이티브 설치 없이 검사할 수 있게 한다. 독립 실행 child에는 PyInstaller 환경 초기화를 지정하고 부모 Tcl/Python 경로를 전달하지 않는다. 이것은 방어 조치이며 다른 PC의 원인으로 확정하지 않는다.
- Setup의 main 이전 import 실패도 얇은 entry wrapper가 구조화해 기록한다. 로컬 진단에는 제품 버전/단계/코드/예외 유형만 넣고 토큰·환경 덤프·미디어 경로·원음은 넣지 않는다. 오류 코드가 없으면 exitCode/명시적 미확인 메시지를 표시한다. 기존 설치/복구 검증을 우회하지 않는다.
- GitHub 제목 Contentrium CUT, 기존 9자산 구분·서명2개·고정v0.1.1 보존. 0.1.109로 새 배포하며 기존 공개 파일을 교체하지 않는다.

## 수용 조건

1. 실제 작은 응답 stream에서 0→실제 bytes→총량 진행 이벤트를 검증. 취소·초과 크기·해시 오류는 실행 불가.
2. child 오류/취소/확인 없음/성공을 구별. import 실패·root 확인 실패의 result가 남고 읽기 전용 diagnose는 실제 설치에 진입하지 않음.
3. headless UI double로 단계/퍼센트/버튼/오류 복사/아이콘 설정과 재시도를 검증. 실제 native UI 시각 검증은 컴퓨터유즈 금지로 수행하지 않았다고 명시.
4. 전체 회귀·독립 리뷰·실제 frozen diagnose/check/download·아이콘 PE/리소스 확인·runtime/CCX/Setup 패키지 검증·공개 download SHA와 서명·v0.1.1을 확인.
5. 해당 다른 PC에서의 설치 성공 및 Premiere 편집·첫 연결·Community-1 품질은 직접 확인되기 전까지 미검증.
